# 推論型ガイド

Graphium の「ナレッジ層」は、ノートから知識を抽出するたびに「どんな推論をして得られた主張か」をメタデータとして付与します。本ドキュメントは、その推論型を「どこに何が住んでいるか」を整理するためのものです。学習教材として読んでも、メタデータの意味を確認するときに開いても構いません。

設計の根は、Graphium の砂時計モデルです: **Notes → 知見 → 洞察 → 発想**。既存データを壊さないために、ディスク上の識別子は `claim` / `atom` / `synthesis` のままですが、ユーザーが見る場面ではこのドキュメントと UI が同じ語彙（知見・洞察・発想）で揃います。各層は文脈の濃度が異なり、推論型もそれぞれの層に固有の意味を持ちます。

---

## 全体像

| 層（UI） | 層（内部） | 操作 | 主な推論型 |
|---|---|---|---|
| Notes → 知見 | `claim` | 抽出 | claimRole（finding / decision / anomaly / question / setup / interpretation / issue）|
| 知見 → 洞察 | `atom` | **抽象化（induction を含む）** | atomType（causal / mechanistic / conditional / …）|
| 洞察 → 発想 | `synthesis` | **異質な要素の統合** | synthesisMode（deductive / abductive / analogical / dialectic）|

特筆点: **induction（帰納）は発想モードではなく、知見 → 洞察 段の中核操作** として位置付けています。理由は本ページ末尾「なぜ induction は発想モードに無いのか」を参照。

---

## 発想の 4 モード（`synthesisMode`）

Synthesizer は洞察（または知見）を入力に取り、**heterogeneous な要素から新しい繋がりを立ち上げる** 層です。同じパターンの反復から一般則を抽出する操作（=induction）は Synthesizer の仕事ではなく、Atomizer の仕事です。

### `deductive`

**演繹（えんえき）**

- 構造: 独立した複数の知見／洞察を入力 → それらから論理的に導かれる戦略・組み合わせを出力
- 例: 「A は X を示す」「B は Y を示す」「C は Z を示す」→「A・B・C を組み合わせると新しい方法 W が成り立つ」
- 哲学的源流: アリストテレス以来の演繹推論。前提が真なら結論も真。
- 限界: 前提のどれかが誤っていれば結論も崩れる。発想に `deductive` を付けるときは前提の確度を確認する。

### `abductive`

**アブダクション（仮説形成）**

- 構造: 観測の知見／洞察（何かが計測された）+ 既知則の知見／洞察（メカニズムや原理）→ 観測を最もよく説明する仮説
- 例: 「Al5Co2 で異常な符号反転が観測された」+「2 バンド伝導はこういう現象を起こす」→「Al5Co2 のフェルミ近傍 DOS は 2 バンド構造を取っているのではないか」（仮説）
- 哲学的源流: パース（C. S. Peirce）。「最良の説明への推論」。**多くの「ひらめき」型の発想はこれ。**
- 限界: 説明候補は無数にあるため、確度は本質的に `speculative`（推測的）。検証は別途必要。

### `analogical`

**類推（るいすい）**

- 構造: 異なる領域の知見／洞察の間にある **構造的写像** を発見し、片方のパターンを他方に転用
- 例: 「永続ストレージの背景メンテナンスは参照構造のフラグメンテーションを段階的に回復させる」（ソフトウェア領域）↔「生体組織のターンオーバーは老廃物を段階的に除去する」（生物領域）→ 両者を貫く転用仮説
- 哲学的源流: アリストテレスの類推、Gentner の structure-mapping theory。
- 限界: 表面的な類似で誤ったマッピングを引いてしまうリスクが高い。rationale に「どの要素がどの要素に対応するか」を明示すること。

### `dialectic`

**弁証法的止揚（しよう）**

- 構造: 同じ効果について **逆向きの主張をする** 2 つの知見／洞察 → 両者を含む上位枠組み
- 例: 「pH を上げると還元が遅くなる」+「pH を上げると還元が速くなる」→「pH 11 を境に律速段階が水酸化物脱離から電子移動に切り替わる」
- 哲学的源流: ヘーゲルの弁証法。テーゼ・アンチテーゼの止揚。
- 限界: 真に矛盾する知見でないと適用できない。強調の違い程度を「対立」と誤認しないこと。

## なぜ induction は発想モードに無いのか

初期設計（提案 v4 の最初の版）では、発想層に `inductive` モードを置いていました: 「3 件以上の知見が同じパターンを示すとき、それを一般則化する」。

しかし実装を進める中で、Atomizer の役割定義をよく読むと:

> 洞察（`atom`）: 複数の知見にまたがって繰り返し現れる、文脈を削いだ単一アイデアを factor out した薄い substrate

これはまさに induction です。Atomizer は「N 件の知見の共通抽象を M 件拾い上げる discovery 層」として動いていて、これは「複数の類似事例から一般則を立てる」と同じ操作になっています。

つまり、発想-inductive と Atomizer が **同じ仕事をしようとしていた**。タクソノミーとして冗長で、ユーザーには「同じ操作なのに名前が違う 2 つの選択肢」を見せてしまっていました。

そこで PR-B4 で整理し:

- 発想のモードを 4 つ（deductive / abductive / analogical / dialectic）に絞る
- Induction は洞察層の核心操作として位置付ける
- Atomizer プロンプトに **「induction-from-many（多くの類似事例から）」「lift-from-few（少数だが domain-lift で）」** の二経路を明示
- UI で洞察の「derived from N 件の知見」表示で induction の事実が見える

設計判断としての含意:
- **知見層**: 文脈付きの個別事実
- **洞察層 = くびれ**: 文脈を剥ぎ、複数事例を **一般則化** する場所。induction の操作はここで起きる
- **発想層**: 異質な要素を編んで **新しい繋がり** を立てる場所

induction と他の推論型（deduction / abduction / analogy / dialectic）は、もはや同列の「発想モード」ではなく、**異なる層に住む別種の操作**である、というのが今の整理です。

> 命名についての補足: 内部のフィールド名（`atomType` / `synthesisMode`）は UI のリネームより前から使われており、保存データの安定識別子として `atom` / `synthesis` の語をそのまま残しています。コードや PROV-JSON-LD エクスポートを読むときはこちらの語彙が出てきます。本ドキュメントや UI を読むときは「洞察 / 発想」と読み替えてください。

## メタデータの読み方

各 Wiki ノートの WikiBanner に表示されるバッジは、本ページの語彙とそのまま対応しています。

- **知見** のバッジ: `claimRole` の値（発見・観察 / 決定・選択 …）
- **洞察** のバッジ: `atomType` の値（因果 / 機構 …）
- **発想** のバッジ: `synthesisMode` の値（演繹 / アブダクション / 類推 / 弁証法）

バッジが表示されないノートは、AI が型を推定できなかった or 該当しないと判断したノートです。後から手動で型を付ける UI は現状ありません（必要になれば追加する予定）。
