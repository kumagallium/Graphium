Graphium vocabulary (graphium:)

Namespace

Namespacehttps://graphium.app/ns#
Prefixgraphium:
Machine-readablegraphium.ttl (RDFS / OWL, Turtle)

Graphium writes its notes and plans as W3C PROV in JSON-LD. Where PROV-O, P-Plan, Web Annotation and Dublin Core have no word for something, the export adds a graphium: annotation. The standard parts are written first and stand alone: a reader who has never heard of graphium: can still read what happened from the standard terms, and loses only the extra notes defined here.

A graphium: key is written only when it has a value; there are no empty placeholders. The same prefix is also used for the identifiers of the things in an export (graphium:note/<noteId> and so on). Those are instances, not vocabulary; they are listed under IRI patterns and are not meant to be looked up.

Classes

ClassMeaning
WarningA problem found while the plan export was assembled (for example two rows with the same name). It has a graphium:warningType and, when they exist, graphium:step, graphium:name and graphium:note. It deliberately has no message text, because the text would depend on the UI language.
TranscriptionThe kind of an Activity that Graphium makes by itself when a note holds a meeting recording: the speech-to-text step between the recording and the text. It is the value of prov:type on that Activity in Graphium's generated PROV graph (the PROV-JSON-LD file export at 2026-10-29 does not copy prov:type). Readers that only know PROV see an ordinary Activity.
FragmentSchemeThe class of a fragment identifier scheme that a Web Annotation fragment selector can declare with dcterms:conformsTo. The only instance defined here is block-id.

Each row has an anchor, so a term can be linked as https://graphium.app/ns#<term>, for example https://graphium.app/ns#blockId. "Used on" says what the property is written on; the types are PROV and P-Plan types unless noted.

Conventions

graphium:<column name>

The parameter table of a step becomes keys of its node. The column name is used as it is, so a column named "temperature" gives graphium:temperature, and a column named "温度 (℃)" gives graphium:温度 (℃). These keys are open-ended and are not defined term by term. A name with a space or another character that an IRI cannot hold is not a valid IRI, and JSON-LD processors drop such a key. So in the export of a note or a plan the same value is also written under graphium:parameter as a pair of label and value. The original key is kept.

IRI patterns

Identifiers are written with the graphium: prefix. A part of an identifier that holds free text (a title, a name, a URL) is percent-encoded.

PatternWhat it identifies
graphium:note/<noteId>A note. A plan note is also the plan. noteId is the note's file id without a wiki: or skill: prefix.
graphium:note/<noteId>/text/<hash>The text of the whole note body. The hash is the one the revision log uses, so the same text always gets the same IRI.
graphium:note/<noteId>/<internal id>A node of the note's own procedure graph: activity_<blockId>, entity_<tableBlockId>_<row name>, inline_<label>_<entityId>, result_<...> and so on.
graphium:note/<noteId>/output/<entityId>A stub for an output of another note that this note took a copy of.
graphium:note/<noteId>/collection/<tableBlockId>A table whose rows are Entities, as a prov:Collection.
graphium:note/<noteId>/import/<tableBlockId>The source file of an imported table.
graphium:note/<planNoteId>/step/<name>A Step of a plan: a row of the operation table. The name is the row name, normalized the same way the plan graph matches names.
graphium:note/<planNoteId>/var/<from>/<to>A planned line between two steps, as a p-plan:Variable.
graphium:note/<planNoteId>/warning/<n>A graphium:Warning, numbered within the plan.
graphium:memo/<captureId>A memo, as a Web Annotation.
graphium:<mediaType>/<fileId>A material or an external source. The first part is the media type (pdf, image, video, audio, document, data, file) or the kind of source (url, chat, memo, shared).
graphium:url/<url>A web page used as a source. The URL is percent-encoded.
graphium:folder/<name>A folder of the app, as a prov:Location.
graphium:agent/person/<sha1>A person. The part after person/ is the SHA-1 of the e-mail address; the address itself is never written. graphium:agent/person/anonymous when there is no identity.
graphium:agent/<model>An AI model as an Agent.
graphium:chat/<noteId>/<chatId>An AI chat, as a prov:Collection. Its messages are .../msg/<timestamp>. Not to be confused with graphium:chat/<key>, the stub of a chat that a Knowledge entry was made from.
graphium:wiki/<title>A Knowledge entry, in the export made from the app's menu. The plan export and the MCP export use graphium:note/<id> for the same entry.
graphium:documentProvenance/<title or noteId>The edit log of a note, as a prov:Bundle: the title in the export of one note, the note id in the plan export. A Knowledge entry's log is graphium:documentProvenance/wiki/<id>. Every node inside a Bundle has the Bundle's IRI as a prefix.
graphium:template/<id>A template a note was made from.
graphium:shared/<id>A shared note a note was made from.
graphium:import/<hash>An intake path (a page fetched from a URL, for example) a note was made from.

Fragment identifier scheme block-id

block-id
(https://graphium.app/ns#block-id)		An instance of graphium:FragmentScheme. The value of a fragment selector that declares this scheme is the id of a block in the note. Together with the IRI of the note it points at exactly one block. A memo about a block carries two selectors side by side: an oa:FragmentSelector that says dcterms:conformsTo this scheme, and an oa:CssSelector with [data-id="<blockId>"].

Related vocabularies

  • PROV-O. The main vocabulary. It is written in the spelling of PROV-JSON-LD, and the context of the export defines the terms it uses locally so that typing does not depend on a remote fetch.
  • P-Plan v1.3 (p-plan: = http://purl.org/net/p-plan#), for planned procedures. The export follows the N3 file of the ontology where the HTML specification differs, so the property is spelled p-plan:isPreceededBy, with two e, as in the official ontology. Graphium only refers to the IRIs. The ontology is not copied or bundled.
  • Web Annotation (oa: = http://www.w3.org/ns/oa#), for memos. The terms are written as oa: CURIEs. The Web Annotation context (anno.jsonld) is not loaded, because its bare keys such as body and target collide with PROV. Expanding the memo to RDF gives the same triples as the annotation context would.
  • Dublin Core. dc: (http://purl.org/dc/elements/1.1/) takes strings: creator, date, publisher, identifier, format. dcterms: (http://purl.org/dc/terms/) is used for references and times: isPartOf, conformsTo, creator, created, modified.

Machine-readable

The same terms are defined in RDFS and OWL in graphium.ttl (Turtle, https://graphium.app/ns/graphium.ttl). The ontology IRI is https://graphium.app/ns#. This page and the Turtle file list the same terms.
