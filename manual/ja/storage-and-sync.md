# 保存と同期

Graphium は、ノートを自分の手元の場所に保存します。保存先は、ブラウザのデータベースか、ディスク上のふつうのファイルです。Graphium のクラウドもアカウントもありません。

このページでは、次のことを説明します。

- 環境ごとのデータの置き場所と、その移し方
- アーカイブとゴミ箱で、リンクが切れないように守る仕組み
- チームで共有する方法
- 全体のバックアップの取り方

## データの保存場所

| 環境 | ノートの保存先 | 届く範囲 |
|---|---|---|
| ブラウザ版 | そのブラウザのローカルデータベース（IndexedDB） | その端末のそのブラウザだけ |
| デスクトップアプリ | 書類フォルダの中の `Graphium` フォルダにあるふつうのファイル（macOS では `~/Documents/Graphium/`） | そのマシンだけ。ただし同期フォルダを指定すれば、どのマシンからでも |

### ブラウザ版

ノートは、ブラウザ自身の IndexedDB に置かれます。データがマシンの外に出ることはありません。ただし、保存領域は 1 つのブラウザプロファイルに属します。

::: warning サイトデータを消すとノートも消えます
ブラウザでこのサイトのデータを消したり、プライベートウィンドウを使ったりすると、そこに保存されていたノートは失われます。ブラウザ版で作業する場合は、定期的にバックアップをダウンロードしてください（下の[バックアップを取る](#backing-up)を参照）。
:::

### デスクトップアプリ

デスクトップアプリは、ファイルマネージャーで見えるふつうのファイルを書き出します。Graphium フォルダの中には、次のサブフォルダがあります。

- `notes`: ノート 1 件が 1 つの JSON ファイル
- `media`
- `wiki`: ナレッジのページ
- `skills`
- `appdata`

ただのファイルなので、どんなバックアップツールでも同期ツールでも扱えます。

## 保存先フォルダを変更する <Badge type="tip" text="v0.3.10 (2026-04-25) で追加" /> {#changing-the-storage-folder}

デスクトップアプリでは、データフォルダごと保存先を変えられます。**設定** → **ストレージ** → **ノートの置き場所** を開き、**変更…** を押します。現在のパスとデフォルトのパスが表示されます。**デフォルトに戻す** を押すと、書類フォルダに戻せます。

![設定ダイアログのストレージタブ。上にノートの置き場所（保存先フォルダと変更ボタン）、その下に書き出しとバックアップ、スマホやブラウザから送る、詳しい設定が並ぶ](/screenshots/settings-storage.png)

切り替える前に知っておくことが 2 つあります。

- 既存のノートは自動では移動しません。作業を続ける前に、古いフォルダの中身を新しいフォルダにコピーしてください。
- 変更後は Graphium を再起動してください。再起動すると、変更が全体に反映されます。

::: tip クラウドのアカウントなしで同期する
設定の説明文にあるとおり、保存先を Dropbox・Google Drive・OneDrive の同期フォルダにすれば、ノートはマシンをまたいで使えます。OAuth も追加のサービスも要りません。Graphium 自身がクラウドとやり取りすることはなく、同期は各サービスのクライアントが行います。
:::

## 著者情報

ノートには、誰が書いたかが記録されます。**設定** → **共有** を開き、**あなたの名前** を開いて、**表示名** と **メール** を入力します。最後に **名前を保存** を押します。

この情報は、共有したノートと、PROV の来歴エントリに記録されます。来歴エントリは、誰が何を編集したかの記録です。詳しくは[ラベルと来歴](/ja/labels-and-provenance)を参照してください。入力した名前は自己申告です。ログインや本人確認はありません。

チームとノートを共有する（後述）には、先にこの名前とメールの登録が必要です。

## ノート一覧のインデックス

ノート一覧は、ノートファイルから作った軽いインデックスをもとに表示されます。Graphium は、作業中もこのインデックスを最新に保ちます。インデックスが失われたり古くなったりしても、次にアプリを読み込んだときに自動で作り直されます。

正しい内容のもとになるのは、常にノートファイル自身です。一覧が古くなったり壊れたりしても、再起動で直ります。アーカイブやゴミ箱の状態も、作り直したあとに残ります。

## アーカイブとゴミ箱

ノートをそのまま消すと、そのノートを指していたリンクと引用がすべて切れてしまいます。そのため Graphium では、2 種類の「消さずに片付ける」操作を使います。

| 操作 | 何が起きるか | リンクは生きるか |
|---|---|---|
| **アーカイブ** | 一覧からは隠れるが、完全に読める状態で残る | はい。参照も引用も、そのまま開ける |
| **ゴミ箱へ移動** | ノートは使わないものとして扱われ、復元バナー付きの読み取り専用で開く | いいえ。そのノートへのリンクは切れた扱いになる |

どちらもノートの `⋯` メニューにあります。**アーカイブ** と **ゴミ箱へ移動** です。ゴミ箱に移すノートを他のノートが参照している場合、Graphium は実行前に、何件のリンクが切れるかを警告します。

戻したいときは、サイドバー下部の **ゴミ箱・アーカイブ** を開きます。

- **ゴミ箱** タブには、**復元** と **完全に削除** があります。
- **アーカイブ** タブには、**アーカイブから復元** と **ゴミ箱に送る** があります。

ゴミ箱やアーカイブのノートを直接開いたときも、`⋯` メニューに **ゴミ箱から復元** / **アーカイブから復元** が出ます。

![Trash & Archive の Trash タブ。3 件のノート（Starter feeding draft / Proofing box scratch notes / Bagel dough trial）が Deleted 列・References 列つきで並び、2 行目がチェックされて Restore と Delete permanently が押せる状態。](/screenshots/trash-archive.png)

元に戻せなくなるのは **完全に削除** だけです。デスクトップアプリでは OS のゴミ箱に送られますが、ブラウザ版ではすぐに削除され、元に戻せません。

メディアにも同じ保護があります。[素材ライブラリ](/ja/materials-and-citations)で、ノート・残した時点・[自分のテンプレート](/ja/notes-and-editor#templates)がまだ使っているファイルを削除しようとすると、代わりに **アーカイブ（推奨）** が提示されます。アーカイブすると一覧からは隠れますが、それらの参照はそのまま生きています。

## チームとノートを共有する <Badge type="tip" text="v0.6.0 (2026-05-05) で追加" /> {#sharing-notes-with-your-team}

共有を使うと、チーム全員が届くフォルダに、ノートのコピーを公開できます。フォルダは、研究室の NAS でも、Dropbox の同期フォルダでも、ほかの共有ドライブでもかまいません。今のところデスクトップ版だけで使えます。ブラウザ版は、ローカルフォルダを読み書きできないためです。

### 共有フォルダを設定する

**設定** → **共有** を開き、**共有フォルダ** で次の順に進めます。

1. **フォルダを選択**（2 件目からは **共有フォルダを追加**）を押し、チームから見えるフォルダを選びます。公開したノートは、このフォルダに置かれます。その行に名前の入力欄が出て、フォルダの名前が入っています。そのままでも、用途に合う名前に書き換えてもかまいません。Enter で確定します。
2. ほかに設定するものはありません。共有するものに画像や PDF などが入っているときは、Graphium が初めて必要になったときに、共有フォルダの中に `_blobs` フォルダを作ってそこに置きます。読める人は、共有フォルダと同じです。別の場所に置きたいときは、行を押して詳しい設定を開き、**大きなファイルの置き場（画像・PDF など）** の **別の場所を選ぶ** を使います。**共有フォルダの中に戻す** を押すと元に戻せます。置き場を決めたあとは、同じボタンが **変更** になります。 <Badge type="tip" text="v0.123.1 (2026-11-06) で変更" />
3. **接続を確かめる** を押すと、そのフォルダで書き込み・読み出し・照合・削除の往復テスト（write → read → verify → delete）を行います。

共有フォルダは、1 件 1 行で並びます。行には、次の内容が出ます。

- 状態の印: フォルダが見えていれば緑、見えなければ橙
- 名前と場所
- 中にあるノート・ナレッジ・テンプレート・素材の件数

行の端の `⋯` メニューには、**名前を変える**・**既定の共有先にする**・**接続を確かめる**・**外す** があります。

![設定の Sharing タブ。Your name（Ken Sato）の Display name・Email・Save your name の下に、Shared folder の 2 行が並ぶ。「Whole bakery」（/Volumes/Bakery/Shared、Default）は開いていて、Location には Change・Check connection、Large files folder には Change・Check connection・Use the shared folder がある。「Sourdough team」（/Volumes/Bakery/Sourdough）は閉じている。その下に Add a shared folder と、共有フォルダの中身を ⌘K と AI チャットに含めるチェックがある。](/screenshots/settings-shared-folders.png)

共有するには、先に「著者情報」の名前とメールを保存しておく必要があります。共有エントリに、著者の名前とメールが付くためです。

共有フォルダの中身を読むだけなら、フォルダへの読み取り権限だけで足ります。自分からは共有しないメンバーは、そのアカウントで書き込めないフォルダのままでかまいません。Graphium がサブフォルダを作るのは、何かを書き込むときだけです。

共有フォルダを開くときに「共有フォルダに到達できません」と出たら、次の 2 点を確かめてください。

- そのパソコンで、ドライブがマウントされているか
- 選んだときと同じパスか

NAS 自体は Finder やエクスプローラーに見えていても、スリープ復帰や再起動のあとに共有のマウントが外れている、というのがいちばん多い原因です。

案内には **再接続** ボタンが出ます。一度でも読み込みに成功した共有なら、Graphium がその接続先を控えています。接続先は、`smb://…` や、ネットワークドライブの `\\サーバー\共有` です。Finder やエクスプローラーに開き直しを頼み、見えたら自動で読み直します。

2 台目のパソコンで、NAS が別の名前（`Kumagai-1` など）でマウントされていることもあります。そのときは、同じ中身がありそうなパスを候補に挙げます。**このパスを使う** を押すと切り替えられます。

### 読める人ごとに共有フォルダを分ける <Badge type="tip" text="v0.122.0 (2026-11-06) で追加" /> {#several-shared-folders}

組織では、全員が読めるフォルダが 1 つとは限りません。組織全体で読めるフォルダのほかに、部署の人だけが開けるフォルダがある、という形がよくあります。そうしたフォルダは、それぞれ登録できます。**共有フォルダ** の **共有フォルダを追加** を押し、見分けがつくように名前（「組織全体」「部署 A」など）を付けてください。

- **誰が読めるかは、フォルダそのものが決めます。** NAS や共有ドライブの権限で決まります。Graphium の中には、権限の設定がありません。名前は、自分の画面で使う呼び名です。
- **初めて共有するときに、置き場を選べます。** 共有フォルダが 2 件以上あると、ノート・ナレッジページ・素材の **チームと共有** は、先に **どの共有フォルダに共有しますか？** と聞きます。素材・まとめて共有のダイアログにも、同じ選択欄が **共有先** として出ます。ノート・ナレッジページ・素材を置けるのは、1 つの共有フォルダだけです。最初に選ばれているのは既定の共有先で、一覧の 1 件目に印が付いています。**既定の共有先にする** を押すと、ほかのフォルダを先頭に移せます。共有フォルダが 1 件だけなら、何も聞きません。

  **テンプレートとして共有** では、共有先を複数選べます。選んだフォルダそれぞれに、別々のテンプレートとして置かれます。たとえば、1 つのテンプレートを組織全体と部署の両方へ一度に配り、知見は部署のフォルダだけに置く、といった分け方ができます。

  ![ノート「Sourdough starter log — day 3」の「どの共有フォルダに共有しますか？」ダイアログ。共有先として「Whole bakery」（/Volumes/Bakery/Shared、既定の共有先）が選ばれ、もう 1 つの選択肢に「Sourdough team」（/Volumes/Bakery/Sourdough）がある。誰が読めるかはフォルダの権限で決まるという注記と、キャンセル・共有するのボタンがある。](/screenshots/share-to-folder-dialog.png)
- **それ以外の操作は、エントリがあるフォルダで行われます。** 次の操作は、そのエントリがある共有フォルダと、そのフォルダの大きなファイルの置き場を使います。
  - 共有コピーの更新、共有解除
  - コメント
  - 変更の提案（元のノートと同じフォルダに置かれます）
  - 引用、fork
  - 共有テンプレートからの新規作成
- **共有フォルダの画面には、すべての共有フォルダの中身が並びます。** 2 件以上あると、タブの上にフォルダの切り替えが現れ、1 つのフォルダに絞れます。**範囲** の列には、その行がどのフォルダから来たかが出ます。届かないフォルダがあると、案内にその名前が出ます。そのフォルダの分は、前回読めた一覧を表示します。
- **フォルダをまたぐ引用があると、共有する前に知らせます。** ノート・ナレッジページ・テンプレートが、共有先とは別の共有フォルダにあるエントリを引用していると、Graphium はそのフォルダの名前を出して、共有してよいか聞きます。共有先は読めても、引用先のフォルダは読めない人がいるからです。その人には、引用カードが「見つからない」と表示され、題名だけが見えます。どちらのフォルダが「広い」かは、Graphium には分かりません。読める範囲はフォルダの権限で決まるためです。そのため、フォルダが違えば毎回聞きます。
- **別の共有フォルダへ移せます。** 共有フォルダが 2 件以上あると、共有済みのノートとナレッジページの `⋯` メニューに **別の共有フォルダへ移す** が出ます。移した先で、同じ id のまま共有し直します。元の共有フォルダでは、共有を解除します。そのため、他の人の引用や複製は、そのまま辿れます。元のフォルダに付いたコメントと提案は、元のフォルダに残ります。更新の回数は、移した先で数え直します。
- **外す** を押して消えるのは、Graphium への登録だけです。フォルダの中身は消えません。

![設定 → 共有 に 1 行ずつ並んだ 2 つの共有フォルダ。「Whole bakery」（/Volumes/Bakery/Shared）には既定の共有先の印があり、ノート 3・テンプレート 2 を持つ。「Sourdough team」（/Volumes/Bakery/Sourdough）はノート 2・ナレッジ 1・素材 1 を持つ。どちらの行も先頭に緑の印、末尾に ⋯ メニューがある。その下に「共有フォルダを追加」と、誰が読めるかはフォルダの権限で決まるという注記がある。](/screenshots/settings-shared-folders-list.png)

共有フォルダを 1 つしか設定していなければ、何も変わりません。その 1 つがそのまま既定の共有先になります。

### 公開と取り下げ {#publish-and-unpublish}

ノートの `⋯` メニューを開き、**チームと共有** を選びます。ノートに **共有済み** のバッジが付き、チームメイトの共有フォルダに現れます。メディアを含むノートを共有すると、ファイルは自動で大きなファイルの置き場にコピーされます。手で添付する必要はありません。

共有されたコピーは、共有した時点の内容を写したものです。更新するには、ローカルのノートを編集して、同じメニューから **共有コピーを更新** を選びます。

取り下げるには、共有フォルダの **共有解除** を使います。他のメンバーがすでに見たり、キャッシュしたり、fork したりしている可能性があるため、完全には消せません。Graphium は、その旨を警告します。

共有で渡るものと渡らないものは、次のとおりです。

- 渡るもの: 本文、そこに付いたラベルと手順、置いてあるフォルダ、埋め込んだ画像やファイル
- 渡らないもの: ノートの中でした AI チャット、編集の来歴、残した時点、メモ

共有で渡すのは記録であって、そこに至るまでの過程ではない、という考え方です。

チャットと編集の来歴も一緒に渡したいときは、次のどちらかをします。 <Badge type="tip" text="v0.61.0 (2026-09-08) で追加" />

- **設定** → **共有** の **共有に AI チャットと編集来歴を含める** をオンにする
- まとめて共有のダイアログで、同じ項目にチェックを入れる

どちらも、次に共有するときから効きます。すでに共有済みのノートは、次に **共有コピーを更新** を選んだときに入れ替わります。

### ナレッジページも共有できます <Badge type="tip" text="v0.44.0 (2026-08-25) で追加" /> {#share-knowledge-pages-too}

トピック・知見・洞察のナレッジページ（以前に作られた要約が残っていればそれも含む）も、ノートと同じように共有できます。ページの `⋯` メニューから **チームと共有** を選ぶと、共有フォルダの **ナレッジ** タブに、共有ノートと並んで現れます。**共有コピーを更新** と **共有解除** も、ノートと同じように使えます。

ナレッジページを fork すると、ノートではなく、自分のナレッジに入ります。自分の知見・洞察と同じ場所に並び、検索やグラフにも加わります。

ただし、来歴は引き継ぎません。共有されたページの「出どころ」は、作った人の手元にあるノート・チャット・知見を指しています。その ID は、こちらでは何も指さないからです。fork したページは、来歴を空にした状態から始まります。代わりに、「どこから来たか」を記録します。こうすると、行き先のない参照や、別のページを指してしまう参照が残りません。

引き継ぐものと、こちらで作り直すものは次のとおりです。

- そのまま届くもの: 本文、意味づけの型、手で直した箇所
- 引き継がず、こちら側で作り直すもの: 世界照合の結果、検索用の埋め込み

### まとめて共有する <Badge type="tip" text="v0.44.0 (2026-08-25) で追加" /> {#share-several-at-once}

ノート一覧でノートを、ナレッジの一覧でナレッジページを、チェックボックスで選びます。すると、一括操作のバーに、件数つきの **共有** ボタンが加わります。

共有は 1 件ずつ順に進み、終わると内訳が出ます。内訳は、新しく共有した件数、すでに共有していたものを更新した件数、失敗した件数とその理由です。1 件失敗しても、残りは止まりません。途中でキャンセルもでき、そこまでに共有できたものは、そのまま残ります。

同じ複数選択バーは、素材ギャラリーの一覧表示にもあります。画像やファイルを、1 件ずつではなくまとめて共有できます。

このボタンが出るのは、デスクトップ版で共有フォルダと著者情報（名前とメール）を設定したあとです。共有されるのは保存済みの内容なので、編集中のノートは先に保存してください。

### ページをテンプレートとして共有する <Badge type="tip" text="v0.54.0 (2026-09-04) で追加" /> {#share-a-page-as-a-template}

ノートの `⋯` メニューには、**チームと共有** の隣に **テンプレートとして共有** も並びます。通常の共有は、ページを記録として渡します。テンプレートとして共有すると、ページを「使い回せる雛形」として渡せます。

名前（既定はノートの題名）を入力し、必要なら説明も入力します。ページは、そのままの状態で共有されます。結果や入力済みの値は自動では消えません。渡したくないものは、共有する前に自分で消してください。

同じページをもう一度テンプレートとして共有すると、以前のものを更新するのではなく、新しいエントリが作られます。テンプレートは、元のノートに紐づく、共有した時点の写しではなく、独立した配布物だからです。

### 見る・fork する {#browse-and-fork}

共有フォルダを設定すると、サイドバーのノート・ナレッジ・素材のタブそれぞれに、**共有フォルダ** の項目が現れます。項目の位置は、ノートのタブでは上のほう、ナレッジと素材のタブでは一番下です。押すと、押したタブと同じ種類（ノート／ナレッジ／素材）の共有分が開きます。

チーム全員が共有したもの（ノート・ナレッジページ・文献・データファイル）が、種類ごとのタブに並びます。他人のエントリは読み取り専用です。**自分のノートに複製** を押すと、自分のストレージにコピーされ、自由に編集できます。持っているメディアは、自動でローカルのライブラリに取り込まれます。fork には、その出どころが記録されます。

行をクリックすると、自分のノート一覧と同じように、表の横の詳細パネルで開きます。全画面で読むには、行をダブルクリックするか、詳細パネル上部の **全画面で開く** を押します。自分のノートと同じ場所・同じ幅で表示されます。

右側のレールでは、**コメント・バージョン・手順・逆引き・グラフ** を切り替えられます。既定では **コメント** が開いています。ページを離れずに確認できます。上部のパンくず（**共有 › 共有フォルダ › 題名**）を押すと、表に戻れます。 <Badge type="tip" text="v0.58.0 (2026-09-07) で追加" />

AI モデルを設定していると、レールにもう 1 つ **AI に質問** が並びます。いま読んでいるエントリについて、共有された本文そのものを根拠に聞けます。会話は自分の端末にだけ残り、共有フォルダには何も書き込まれません。詳しくは[共有フォルダのノートについて聞く](/ja/ai-chat-and-ask#asking-about-a-shared-note)を参照してください。 <Badge type="tip" text="v0.59.0 (2026-09-07) で追加" />

![表形式の共有フォルダ。ノートにはフォルダ・作成者・共有日・バージョンの列が並ぶ](/screenshots/shared-library.png)

![共有ノートの全画面表示。右のレールにコメントが開いている](/screenshots/shared-note-full-view.png)

共有されたノートには、共有した時点のフォルダも付いてきます。**ノート** のタブに **フォルダ** 列が並び、そこで絞り込みや検索ができます。fork では、このフォルダは引き継ぎません。共有した人の整理であって、こちらの分類ではないからです。fork したノートは、未分類から始まります。 <Badge type="tip" text="v0.53.0 (2026-09-03) で追加" />

![共有フォルダをフォルダで絞り込む](/screenshots/shared-library-folder-filter.png)

**素材** タブにも、同じくフォルダ列があります。共有ノートに貼られている画像・ファイルが、素材として直接共有されたものと並んで、一覧に出ます。

ノートに貼られたものは、単独で fork や検証ができるエントリではありません。そのため、**ノートを開く** か **自分の素材に取り込む** のどちらかを行います。同じファイルが複数の共有ノートに貼られている場合は 1 行にまとめられ、何件のノートに含まれるかが件数で示されます。 <Badge type="tip" text="v0.54.0 (2026-09-04) で追加" />

**ラベル** と **プロセス** のタブは、自分の左ナビゲーションにある同じ名前の画面と、同じ構成になっています。共有ノートから見つかったラベルと PROV-DM の手順を、自分のノート一覧・プロセス一覧と同じやり方で取り出して表示します。

これらのタブには、次の点があります。

- 後述する共有検索・AI チャットを支えている、バックグラウンドの読み込みを使っています。そのため、Graphium がまだ本文を読んでいない共有ノートは、これらのタブにはまだ反映されません。
- プロセスのタブから自分のノートへ fork する操作は、自分の手順を fork するときと同じです。
- ラベルやプロセスだけを共有する専用の操作はありません。それらを含むノートを共有すれば足ります。両方のタブに、その旨の説明と、自分のノート一覧へ戻るリンクがあります。 <Badge type="tip" text="v0.54.0 (2026-09-04) で追加" />

![共有フォルダのラベルタブ。共有ノートから集まった Input のラベルが並ぶ](/screenshots/shared-library-labels.png)

![共有フォルダのプロセスタブ。共有された手順とその流れ](/screenshots/shared-library-process.png)

**テンプレート** タブには、テンプレートとして共有されたページ（前述）が並びます。**ノート** タブのフォルダ列の代わりに、**説明** 列があります。

このタブには **自分のノートに複製** がありません。テンプレートは、コピーして残す記録ではなく、まっさらな出発点だからです。代わりに、詳細パネルに **テンプレートから新規ノート** があります。自分が共有したものも含めて、どのエントリでも押せます。押すと、テンプレートを読み込み、そのブロックとラベルから新しいノートを組み立てます。埋め込まれたメディアは、自分のライブラリに取り込まれます。そのうえで、新しいノートが開きます。

新しいノートには、どのテンプレートから作られたかが記録されます。ただし、fork の「複製元」とは別の扱いです。テンプレートは、事実を何も引き継がず、形だけを渡すものだからです。

同じテンプレート一覧は、エディタの `/template` ピッカーの中にも出ます。新しいノートを作らずに、開いているノートへ挿入することもできます。詳しくは[ノートとエディタ](/ja/notes-and-editor#templates)を参照してください。 <Badge type="tip" text="v0.54.0 (2026-09-04) で追加" />

![共有フォルダのテンプレートタブ。フォルダ列の代わりに説明列が並ぶ](/screenshots/shared-library-templates.png)

### 検索と AI チャットでの共有エントリ <Badge type="tip" text="v0.52.0 (2026-09-03) で追加" /> {#shared-entries-in-search-and-ai-chat}

共有されたノート・ナレッジページ・文献・データファイルは、fork しなくても検索の結果に出ます。

- `⌘K`（Windows/Linux は `Ctrl+K`）の検索パレットに、**共有** のセクションが増えます。
- AI チャットも、自分のノートと同じように、共有エントリを横断検索の対象にします（Internal のグラウンディングスコープ）。

検索用の索引は、自分の端末上だけに作られます。共有ナレッジページの埋め込みも同じです。共有フォルダには何も書き戻しません。AI が共有エントリを根拠にしても、自分で引用カードを挿入しない限り、PROV には記録されません。

この設定は、共有フォルダを設定した時点で既定オンです。共有フォルダを設定すること自体が、使う意思の表れだからです。検索と AI チャットの対象を自分のノートだけにしたいときは、**設定** → **共有** の **共有フォルダの中身を ⌘K と AI チャットの対象に含める** をオフにしてください。

共有フォルダには、Graphium の中でのアクセス制御がありません。フォルダを読める人は、誰でも同じように索引・検索できる点に注意してください。

### ノートから共有エントリを引用する <Badge type="tip" text="v0.31.0 (2026-08-12) で追加" /> {#cite-a-shared-entry-in-your-notes}

ノート内で `/` を打って **共有エントリを引用** を選ぶと、共有されたノート・文献・データファイルを指す引用カードを挿入できます。カードには、タイトル・作者・日付と、照合バッジが表示されます。

カードは*参照*としてノートに残り、実体は共有フォルダ側にあります。ノート側には、表示用の軽い控えだけを保存します。そのため、共有フォルダに接続できないときも、カードは表示されます。

バッジは、共有側の状態を示します。

- **照合済み**: 共有側の内容が、記録された指紋（hash）と一致しています。
- **内容に差異**: 指紋が一致しません。Graphium を通さない書き換えや、破損の可能性があります。
- **キャッシュ表示**: 共有フォルダに接続できないため（NAS 未マウントなど）、保存してある控えで表示しています。
- **見つかりません**: エントリが削除または共有解除されています。

![共有の引用カードが縦に 4 枚。それぞれ題・著者・日付があり、Verified、Content differs、Cached copy、Not found の表示が付いている。](/screenshots/shared-citation-cards.png)

作者がエントリをその場で更新すると、カードは自動で追従します。

大きな改訂（新しいバージョン）が公開された場合、カードは引用したバージョンを指したまま、**新しいバージョンがあります** と知らせます。過去の解析が、知らないうちに変わることはありません。

カード右端の矢印を押すと、共有フォルダでエントリを開けます。引用はノートの来歴にも記録されます。エクスポートした証拠バンドルには、「どの共有エントリを使ったか」が残ります。

### 共有フォルダから引用リンクをコピーする <Badge type="tip" text="v0.44.0 (2026-08-25) で追加" /> {#copy-a-citation-link-from-the-library}

共有フォルダの側から始めることもできます。**共有** → **共有フォルダ** で、エントリの **引用リンクをコピー** を押します。カードの上でも、詳細パネルでも押せます。コピーしたリンクを、ノートに貼り付けてください。スラッシュメニューから入れたものと同じ引用カードになり、バッジの動きも同じです。

貼り付ける形にしているのは、次の理由からです。共有フォルダの画面は全体を使うので、見ているあいだは貼り先のノートが見えません。そこで、先にエントリを探しておき、置き場所はあとから決められるようにしました。

リンクはただの文字列なので、チャットやメールでチームメイトに渡すこともできます。同じ共有フォルダを見ている相手なら、自分のノートに貼るだけで同じカードになります。

### コメントで返す <Badge type="tip" text="v0.57.0 (2026-09-06) で追加" /> {#reply-with-a-comment}

共有フォルダのエントリには、種類を問わず、コメントのスレッドを付けられます。ノート・ナレッジページ・参考文献・データファイルのどれでも同じです。

詳細パネルを開いて **コメント** まで進み、そのまま書きます。先にプレビュー内の段落をクリックしてからコメントを書くと、その段落に紐づいたコメントになります。何に付いているかを示す「¶」チップが出ます。投稿の前なら、チップは外せます。

返信は 1 段階までです。返信への返信も、同じスレッドにそのまま追加されます。入れ子になった議論にはなりません。

![共有ノートの詳細パネル。プレビューの下にコメントがドックされている](/screenshots/shared-library-detail-comments.png)

コメントを書くには、先に前述の「著者情報」（名前とメール）を登録しておく必要があります。未登録の場合は、パネルにその旨と、設定への案内が表示されます。

コメントに「解決」のチェックはありません。代わりに、次のように動きます。

- ノートの作者が直して **共有コピーを更新** を押すと、ノートの指紋（hash）が変わります。
- 前のバージョンに対して書かれたコメントは、自動的に、折りたたまれた **前のバージョンへのコメント** に移ります。
- スレッド自体は消えません。対応が済んだものが、表から外れるだけです。

自分のコメントは編集・削除できますが、他人のコメントはできません。

自分が共有したノートに誰かがコメントすると、そのノートを編集しているときの右パネルにも、同じスレッドが **コメント** タブとして現れます。そこでコメントをクリックすると、書かれた段落へジャンプし、一瞬ハイライトされます。

前述の全画面表示でも、右側のレールに同じ **コメント** パネルがあります。詳細パネルを開かなくても、読み書きできます。本文の段落をクリックすると、詳細パネルと同じように、「¶」チップがコメントに付きます。

### 更新の履歴と「更新あり」「新着コメント」の印 <Badge type="tip" text="v0.57.0 (2026-09-06) で追加" /> {#update-history-and-the-updated-new-comment-marks}

共有エントリを **共有コピーを更新** で再共有するたびに、Graphium は短い履歴を残します。共有フォルダのバージョン列には、そのエントリが何回更新されたか（例: 「v1 · 更新 3 回」）が表示されます。詳細パネルには、各更新の日時・更新者・指紋（hash）の先頭 8 桁が並びます。

前に見たときから何が変わったかが分かるよう、共有フォルダの行には、次の印も表示されます。

- **更新あり**: 前回開いたときから、指紋が変わったことを示します。
- 新着コメントの件数: 前回開いたときから増えたコメントの数です。

これらの印は、自分の端末だけに残る小さな控えから作られます。共有フォルダには何も書き戻しません。自分が作ったエントリに、自分の更新で「更新あり」が出ることはありません。

共有フォルダは、Graphium のタブや画面に戻ったときに自動で読み直します。手動で再読み込みしなくても、これらの印は最新の状態に保たれます。

![共有フォルダの行に出る「更新あり」と新着コメントの印](/screenshots/shared-library-update-marks.png)

### 逆引き: 誰が引用・複製したか <Badge type="tip" text="v0.57.0 (2026-09-06) で追加" /> {#reverse-links-who-cited-or-forked-this}

あるノートが共有エントリを引用したり、fork したり、共有テンプレートから作られたりすると、その関係を逆の側からも見られます。

共有エントリの詳細パネルには、次のノートが一覧されます。それぞれクリックで、そのエントリへ移動できます。

- そのエントリを引用している共有ノート
- そのエントリから複製された共有ノート
- テンプレートの場合は、そこから作られた共有ノート

この一覧は、引用・複製した側のノートの中身を、Graphium が一度でも読み込んでいることが前提です。そのため、共有されたばかりのノートは、他のエントリの逆引きにすぐには現れないことがあります。

### 変更を提案する <Badge type="tip" text="v0.66.0 (2026-09-08) で追加" /> {#propose-changes}

共有されたノートを自分のノートに複製（fork）して直したものを、**元のノートへの変更の提案**として共有できます。元のノートは書き換わりません。取り込むかどうかは、元を書いた人が決めます。

提案する側の手順は 3 つです。

1. 共有フォルダの画面で元のノートを開き、**自分のノートに複製**を押して自分のノートにコピーを作る
2. コピーを普通に編集する（値を入れる・手順を直す・表を足す）
3. ノートの `⋯` メニューから **元のノートへ変更を提案** を選ぶ

ダイアログには、どのノートへの提案かと、複製した時点の内容が今も元の最新かが出ます。説明（任意の 1 行）を書いて **提案する** を押すと、共有フォルダに、自分の名前の提案が 1 通できます。

提案したあとも、同じメニューから **提案を更新** で出し直せます。**提案を取り下げる** を押すと、取り下げられます。提案として共有している間は、そのノートを「チームと共有」の対象にできません。1 つのノートが指せる共有は、1 つだけだからです。

![「Propose changes to the original」ダイアログ。提案先のノート Sourdough loaf — Saturday bake（Mia Tanaka）、Baseline の行、入力済みの一行説明、Cancel と Propose ボタンが見える。](/screenshots/share-propose-dialog.png)

共有フォルダの画面には、**提案** タブが増えます。並ぶ項目は、タイトル・元のノート（押すと元へ移動できます）・作者・共有日・バージョン・状態です。状態は次の 3 つのどれかです。記録された値ではなく、そのときの内容から判定されます。

| 状態 | 意味 |
|---|---|
| 受け付け中 | 元を書いた人がまだ取り込んでいません |
| 取り込み済み | 元を書いた人がこの提案を取り込みました |
| 元のノートがその後更新されました | 提案を出したあとに元が変わりました |

![共有フォルダの Proposals タブ。ヘッダーに共有フォルダ /Volumes/Bakery/Shared が見え、3 件の提案が表で並び、元のノート・作者・日付・版・状態（Open / Original updated since / Adopted）が見える。](/screenshots/shared-library-proposals.png)

提案を全画面で開くと、右側に **差分** のタブが出ます。ここに、元のノートとの違いが、ブロック単位で並びます。表は、1 マス単位まで細かく比べます。項目を押すと、本文プレビューの該当箇所が光ります。

![Ken Sato の提案をフルビューで開き、右レールの Changes タブにブロック別の 4 件の変更（表のセル単位の差分を含む）が Proposer / Author のバッジ付きで並んでいる。](/screenshots/shared-proposal-diff.png)

複製した時点の内容が控えられていれば、変更は 3 つに分かれて色が付きます。

- **提案者**: 提案した人だけが変えたところです。取り込みの候補になります。
- **作者**: 元を書いた人が、その後に変えたところです。
- **両方**: 両方が変えていて、食い違っているところです。

控えが無いときは、元の現在の内容と 2 つを比べるだけになり、どちらが変えたのかは分けられません。控えが無いのは、大きなファイルの置き場を設定していない場合や、古い複製の場合です。その旨は、差分の先頭に書いてあります。

比べていないものもあります。

- 画像や PDF の参照先（共有側と手元でリンクの形が違うためです。説明文やファイル名は比べます）
- 2 ページ目以降
- ラベルや手順のリンクなどの注釈

元のノートの側から見ると、提案が来ているノートの行には **提案 N** が付きます。詳細パネルの逆引きには、提案の一覧が並び、押すとその提案へ移動できます。

元のノートがその後更新されていても、提案は出せます。そのときは、差分が「元の現在の内容」との比較になります。自分が直したところと、元を書いた人が直したところが、並んで見えます。

全画面の差分は**読むだけ**の場所です。取り込みは、元を書いた人が自分のノートの側で行います。

#### 取り込む（元を書いた人） <Badge type="tip" text="v0.67.0 (2026-09-08) で追加" /> {#adopt-a-proposal}

自分が共有したノートに提案が来ると、そのノートを開いたときに、右側のレールへ **提案** が増えます。提案が 1 件も無いノートには出ません。ヘッダの共有バッジの横にも **提案 N** が出るので、そこからも開けます。

1. 右レールの **提案** を開く。届いている提案が、作者・日時・状態・説明つきで並びます
2. 1 件選ぶ。いま開いているノートとの違いが並びます。比べる相手は、**共有コピー**ではなく、**いま書いているノートの中身**です。更新を押していない編集も入った状態で比べられます
3. 取り込みたい変更にチェックを入れる。最初からチェックが入っているのは、**提案者** だけが変えたものです。**両方**（食い違っているもの）は、自分で判断して入れてください。**作者**（自分が変えたところ）は、取り込む相手がいないのでチェックできません
4. **選んだ変更を取り込む** を押す

![右レールの Proposals タブで提案を 1 件開いた状態。4 件の変更が並び、提案者の変更にはチェックボックス、作者が足した変更にはチェックボックスが無く、下に Adopt selected changes (3) ボタンが見える。](/screenshots/note-proposals-adopt.png)

押すと、まず「取り込む前の状態」が自動で 1 つ残ります。そのあとで、選んだ変更だけがノートに入ります。気が変わったら、`⋯` メニューの履歴から戻せます。取り消しの操作（⌘Z / Ctrl+Z）でも、1 回で戻ります。

表は 2 段階で選べます。

- マス（行・列）ごとに選ぶと、そのマスだけが書き換わります。
- 表そのものの行にチェックを入れると、表が丸ごと提案側の内容に置き換わります。

この 2 つは、同時には選べません。丸ごと置き換えると、自分が足した行も一緒に消えるためです。

取り込んでも、共有した側はまだ変わりません。**共有コピーを更新** を押した時点で新しいバージョンになり、そこではじめて、提案者の画面の状態が **取り込み済み** に変わります。`⋯` メニューの補足に「取り込んだ提案 N 件が新しいバージョンに含まれます」と出るので、押し忘れに気づけます。

提案した側から見ると、状態バッジが **取り込み済み** に変わります。自分のノートはそのまま手元に残ります。続きを書いてもう一度提案してもかまいませんし、`⋯` メニューの **提案を取り下げる** で片付けてもかまいません。

#### 複製元を確かめる {#forked-from}

複製して作ったノートのヘッダには、**複製元: ○○** のチップが出ます。押すと、元の共有エントリが開きます。右パネルの **グラフ** にも、複製元と、自分のノートに来ている提案が、破線でつながって出ます。こちらもクリックで開けます。

## エクスポート

データは、すべて開かれた形式で Graphium の外に出せます。ノート 1 件ずつでも、まとめてでも書き出せます。

ノート単位では、`⋯` メニューの **書き出す** に次の項目があります。

| メニュー項目 | 出力 |
|---|---|
| **印刷・PDF** | 来歴グラフを含む、表示されたとおりのノート。システムの印刷ダイアログが開くので、ページを確かめてから PDF として保存できます。文字は選択・検索できる形で残ります |
| **Markdown（.md）** | 持ち運べる `.md` ファイル |
| **来歴データ（PROV-JSON-LD）** | ノートの来歴グラフを W3C PROV 形式で書き出します。本文・フォルダ・出典・メモ・資料・表といった、ノート自身の記録も入ります（AI チャットは含みません） |
| **計画の PROV を書き出す** | 計画ノートだけ。計画全体（工程・予定の線・工程ノートの来歴）を、`.plan.jsonld` 1 つにまとめます（[計画の PROV を書き出す](/ja/labels-and-provenance#計画の-prov-を書き出す)） |

Markdown は、もともと「見た目」を持ち運べない形式です。ブロックの種類は残りますが、どう見えていたかは残りません。書き出し方は、ブロックによって次のように違います。

- 数式: LaTeX のソースとして書き出します。
- 計算ブロック: 式と、求まった値を書き出します。
- チャート: キャプションと、「何を何に対して描いたか」を書き出します。図そのものは持ち出せません。ただし、元になった表は、ふつうの Markdown の表として残ります。

### すべてを書き出す <Badge type="tip" text="v0.16.10 (2026-07-03) で追加" />

**設定** → **ストレージ** → **書き出しとバックアップ** には、一括のボタンが 2 つあります。

- **全ノートを書き出す (Markdown)**: すべてのノートを Markdown にした ZIP です。どこでも読めます。
- **バックアップをダウンロード (JSON)**: すべてのノート・ナレッジのページ・スキルドキュメントの生データ（`.graphium.json`）を入れた ZIP です。アーカイブとゴミ箱の中身も含みます。情報が欠けない書き出し方です。

メディアファイル（画像・PDF）は、どちらの ZIP にも含まれません。メディアは、次に説明する方法で別にバックアップしてください。

### 選んだノートを書き出す <Badge type="tip" text="v0.101.3 (2026-10-28) で追加" /> {#export-selected-notes}

一部のノートだけを取り出したいときは、**すべてのノート** を開いて、対象にチェックを入れます。出てきたバーの **その他** から、**書き出す（Markdown）** を選びます。

- 1 件なら、`.md` ファイルが 1 つできます。
- 2 件以上なら、1 ノート 1 ファイルの ZIP になります。**全ノートを書き出す (Markdown)** と同じ形です。

書き出したあとも、選択はそのまま残ります。続けて、同じノートをアーカイブすることもできます。

一括の書き出しと同じく、保存されている内容を読みます。開いているノートで直前に編集した分は、保存されてから反映されます。

## バックアップを取る {#backing-up}

- **ブラウザ版**: 定期的に **バックアップをダウンロード (JSON)** を押してください。サイトデータが消えたときの、唯一の備えです。まとまった量を書いたあとは、その都度取り直してください。
- **デスクトップアプリ**: データは、Graphium フォルダのふつうのファイルです（移動していなければ `~/Documents/Graphium/`）。そのフォルダを `media` サブフォルダごとコピーするバックアップツールなら、それだけで全部が入ります。保存先を同期フォルダにしておけば、マシンの外に、常に控えができます。

どの環境でも、ときどき **バックアップをダウンロード (JSON)** を押しておくと、手軽な保険になります。ノート・ナレッジ・スキルが 1 つのファイルに収まり、実データがどこにあるかに左右されません。
