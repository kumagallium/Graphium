# 世界照合

ノートからは知見や洞察が生まれます。では、それは世界がすでに知っていることとどう関係しているのでしょうか。世界照合は、ナレッジの一片を外部の情報源（Wikipedia、OpenAlex、任意で Web 検索）と突き合わせ、判定（verdict）を刻みます。「これは世界ではすでに知られているのか、支持されているのか、それとも争われているのか」に答えるので、どこを深掘りするかを決める材料になります。

verdict は真偽を告げる神託ではなく、位置づけの手がかりとして扱ってください。示されるのは、その主張が知識ベースに対してどこに位置するかです。主張が成り立つかどうかの最終判断は、常に自分の手元にあります。

::: info 必要なもの
世界照合は Graphium の AI 機能の一部なので、[デスクトップアプリ](/ja/desktop-app)と、登録済みモデルが 1 件以上必要です（[AI のセットアップ](/ja/ai-setup)を参照）。Wikipedia と OpenAlex からの根拠は API キーなしでそのまま使えます。Web 検索の MCP サーバー（たとえば Tavily）を追加すると、根拠の範囲が一般の Web まで広がります。**設定** → **AI** の **世界照合を使う** スイッチにもゲートされていて、初めて使うときはオフ、以前から使っている場合はオンです。下で説明する **世界照合** ボタンが見当たらないときは、まずこれをオンにしてください。
:::

## 主張を世界と突き合わせる <Badge type="tip" text="v0.8.0 (2026-05-21) で追加" />

ナレッジの項目 — サイドバーの **ナレッジ** の下にある **知見** または **洞察** — を開き、本文の上にあるバナーを見ます。**再生成** の隣に **世界照合** ボタンがあります。

![エディタで開いた知見。バナーに世界照合ボタンと verdict チップが並んでいる](/screenshots/world-grounding-verdict.png)

クリックすると照合が走り、結果がその項目に保存されます。保存されるのは verdict・理由・出典です。実行中は進捗トーストが状況を伝えます。**要約**（現在は新規生成を停止しているページの種類。詳しくは[ナレッジ層](/ja/knowledge-layer)を参照）も照合できません。要約は世界について何かを主張するものではなく、自分のノート 1 件を説明するものだからです。

複数の項目をまとめて照合することもできます。知見・洞察の一覧には **世界** 列があり、各行の最新の verdict を表示します（verdict の強さでソートできます）。チェックボックスで行を選び、件数付きの **世界照合 (n)** をクリックします。もう一度実行すると前の verdict を上書きするので、このボタンは「付け直し」も兼ねます。

## verdict を読む

verdict はバナーのチップとして表示され、知識ベース側の立場という形で言い表されます（チップにカーソルを合わせると **KB から見た位置づけ** と理由が見られます）。

| チップ | 意味 |
|---|---|
| **確立した知識と整合** | 教科書レベルに確立した知識と噛み合っている。 |
| **支持された知識と整合** | 公表された裏付けはあるが、そこまで定まっていない知識と噛み合っている。 |
| **KB は裏付けが弱いと見る** | 知識ベースが見つけた裏付けは、弱いものだけだった。 |
| **KB に反例がある** | 知識ベースが、この主張に反する証拠を持っている。 |
| **照合済 · KB マッチなし** | 照合は走ったが、一致するものがなかった。支持も反証もされていない。 |

全体像を見るには、項目の一番下までスクロールします。**世界照合 詳細** のセクションに、**理由**、**参考文献**（それぞれ開けるリンク）、**マッチした語彙**、そして **照合元** が並びます。照合元を見れば、その答えがローカルの知識ベースから来たのか、Web の根拠に裏打ちされた判定から来たのか、モデルが自分の知識で答えたのかが分かります。

2 つの洞察が同じ世界の事実に接続したとき、Graphium はそれらを結びます。**同じ世界事実に接続した洞察 (n)** のセクションに、世界の同じ一点に触れた他の洞察が並びます。これは、孤立した AI の回答が代わりに保持しておけない類のつながりです。

## 出典照合: 出典に実際に書いてあるか <Badge type="tip" text="v0.77.0 (2026-09-17) で追加" />

世界照合は、主張が外の知識に照らして成り立つかを問います。**出典照合** はもっと狭い、別の問いを立てます——このナレッジ項目自身が引いている出典に、実際にそう書いてあるか。外部の知識には一切触れず、命題が正しいかどうかも判定しません。判定するのは「引かれた出典に書いてあるかどうか」だけです。

対象は **知見** と **トピック** だけです。知見は全体を 1 つとして照合します（title と本文を、**由来** に並ぶすべての出典ノートと突き合わせます）。トピックは文ごとに照合します——本文中の（**参考文献** セクションより前にある）各文のうち、メンバーの知見を引用しているものだけが照合対象になり、その知見自身の本文と突き合わされます。引用はリンクでも、文の直後にその知見のタイトルがそのまま文字として置かれている形でも認識します。何も引用していない定義の段落は照合しません。**洞察は対象外です**——洞察は複数の知見をまたいだ一般化であって、1 つの出典の言い換えではないため、突き合わせる相手となる出典テキストがそもそも存在しません。

実行は、知見・トピックのバナーにある **出典照合** ボタン（AI が使えるときだけ表示。**世界照合** の隣）か、**手入れ** 画面の **出典照合** タブ（後述）から行います。既定では取り込み時にも起動時にも自動では走らず、結果が出るのは自分で頼んだときだけですが、設定の **自動で出典照合する**（既定オフ。後述の「自動で出典照合する」を参照）をオンにすると自動でも走るようになります。AI をオフにするとボタンは消えますが、すでに記録した結果はそのまま表示され続けます。

**バッジの読み方。** 出典照合ボタンの隣のバッジは、次の 5 つの判定のいずれかを示します。

| バッジ | 意味 |
|---|---|
| **出典と異なる** | 引かれた出典が、この主張と食い違うことを積極的に述べている。5 つの中でいちばん目を引く色にしてあります——主張が自分の出典と食い違っているのは、いちばん驚くべき結果だからです。 |
| **出典に見当たらない** | 出典は読めたが、そうは書かれていない。 |
| **出典に書かれている** | 出典にそう書かれている。 |
| **判定できなかった** | 出典は読めたが、どちらとも判定がつかなかった。 |
| **出典を開けなかった** | 出典そのものを照合できなかった（理由は下記）。 |

項目の下部にある **出典照合 詳細** を開くと、出典ごとの内訳——判定・短い理由、そしてモデルの引用がノートの特定ブロック 1 つに絞り込めたときは **該当箇所へ** のリンク——が並びます。このリンクが開くのは、リンク先のノート・PDF・Word ファイル・知見であって、その中の特定のブロックまで自動でスクロールする仕組みは既存に無いため、開くところまでで止まります。開けない出典（記録が無い・AI チャット由来・裏づけのノートが残っていない ⌘K の回答）はリンクとして表示されません。トピックでは、各エントリに照合した **文**（ページ全体ではなく、その特定の 1 文）も表示されます。

出典が PDF や Word ファイルのときは、引用の直下にその出典のどこにあったかも表示されます——たとえば **12 ページ**、**12〜13 ページ**、**第 3 段落** のように。これはモデルに書かせたものではなく、照合がその場で読んだ原文から機械的に割り出したもので、判定には影響しません。該当箇所を探しやすくするための表示です。まったく同じ文言が出典の中に複数箇所（別のページや段落）にあるときは、どちらを指しているか決められないため、この表示自体が出ません。

**「出典を開けなかった」の内訳。** 次はいずれも判定そのものを試みず、そのまま記録されます。

| 理由 | いつ起きるか |
|---|---|
| 出典が見つからない（削除・ゴミ箱） | 引かれたノート・PDF・Word ファイル・知見がゴミ箱にあるか、既に存在しない |
| 元の会話を辿れない（AI チャット由来） | 出典が AI チャットで、元をたどる参照キーを Graphium が持っていない |
| 原文を読み出せなかった | URL の再取得や PDF/Word の再抽出に失敗した |
| 照合できない種類の出典 | 出典照合が扱わない種類の ID |
| 出典の本文が空 | 出典は読めたが、中身が空だった |
| AI の回答から作った知見（原文なし） | その知見が ⌘K の回答から作られたもので、回答そのものは保存されていないため、回答を出したノートと突き合わせると誤って「見当たらない」と判定してしまう |
| 出典の記録が無い | 知見に引いたノートが 1 件も無い、またはトピックのその文がメンバーの知見を 1 件も引用していない |

出典照合は毎回、原文をキャッシュに頼らず取り直します——PDF と Word は取り込みと同じ抽出器で、URL は以前保存したコピーではなく実際に取り直した内容で突き合わせるので、判定は「今その URL に何が書いてあるか」を映します。これらの取り直しに、出典照合が独自の上限を足すことはありません——ノート・Word・Web ページは全文を、PDF は取り込みと同じ 80,000 字の上限（[よくある質問](/ja/faq)を参照）まで読むので、取り込みが読んだのと同じ範囲と突き合わせます。

判定を始める前に、必要になりそうな判定回数の見込みが表示されますが、出典を取り出せなかった分は判定せずに飛ばすため、実際の呼び出し回数は見込みより少なくなることがあります。

**トピックのバッジは、いちばん出来のよい文ではなく、いちばん注意が要る文を映します。** トピックには照合済みの文が複数あり、それぞれ別の判定を持ちえます。ページのバッジは、それらを平均したり、良い結果に悪い結果を隠させたりせず、いちばん注意が要るものを表示します——1 文でも「出典と異なる」「出典に見当たらない」になれば、他の文がすべて「出典に書かれている」でも、そちらが勝ちます。トピック全体が「出典に書かれている」になるのは、すべての文がそうなったときだけです。知見は文が 1 つしかないので、この集約は知見自身のバッジの見え方を変えません。

**まとめて照合する。** 知見・トピックの一覧には **出典照合** 列があり、最新の判定を表示します。並べ替えも注意が要る順です——**出典と異なる** → **出典に見当たらない** → **判定できなかった** → **出典を開けなかった** → **出典に書かれている**。サイドバーの **手入れ** を開き、**出典照合** タブに切り替えると、**対象**（知見・トピック・両方）と **範囲**（まだ照合していないもの・本文が変わったもの・すべて）を選び、件数・判定回数・照合できない内訳を含む実測の計画を確認してから、中断可能な進捗表示つきで実行できます。このタブは **点検** タブの既存のクイック / フル点検とは別で、そちらには一切つながりません。1 件の実行と一括実行は同時には走らず、片方が動いている間はもう片方が止まります。

**結果への対処。** 世界照合と同じく、出典照合の判定にどう対処するかはあなた次第です。**もう一度照合** は再実行して古い結果を置き換え、**確認した** は内容を変えずに確認済みの印を付け、**結果を消す** は結果そのものを削除します。どの知見を直すか、どの出典を信じるかを Graphium が代わりに決めることはありません。

**気になる判定でも一覧からは隠しません——要確認に入るだけです。** 「出典と異なる」「出典に見当たらない」と判定された知見・トピックも、他の一覧からは消えません。AI の判定が間違っている可能性があり、こっそり一覧から消えた知見はそれでもトピックやチャットに使われ続けてしまうためです。代わりに **出典照合** タブが常設の **要確認** 一覧を保持し（出典と異なる→出典に見当たらないの順）、行ごとに **開く**・**確認した**・**アーカイブ**・**もう一度照合** を、まとめては複数選択してのアーカイブを用意しています。ここでのアーカイブも他の画面と同じ可逆なアーカイブ（いつでも戻せます）なので、何を消すかは常に自分で決められます。知見・トピックの一覧にも、既定オフの **要確認のみ** フィルターがあります。

## 自動で出典照合する <Badge type="tip" text="v0.77.0 (2026-09-17) で追加" />

既定では、出典照合は頼んだときだけ走ります。新しくできた・変わったナレッジを自動で照合したい場合は、**設定** → **AI** を開き、**世界照合** セクションの **自動で世界照合する** の直下にある **自動で出典照合する** をオンにします（既定はオフ）。

オンにすると、新しく作られた・更新された知見とトピックが、バックグラウンドで 1 件ずつ、出典 1 件ごとに AI を呼びながら出典照合されます。まだ照合していないものも順に対象になります。手動の 1 件照合・一括照合とは同時には走りません。本文を書き換える取り込み（統合・書き直し・トピックの再構成）で結果が消えたものも、再び自動照合の対象になります。

## 仕組み: 育つ知識ベース

世界照合は 2 層で作られています。この構造が分かると、使うほど速くなる理由も見えてきます。

1. **まずローカルの知識ベースが答える。** 照合はすべて、ローカル KB（小さな手キュレーションの seed と、これまでの照合でキャッシュされたものすべて）との突き合わせから始まります。ヒットすれば即答、コストゼロ、モデル呼び出しなしです。
2. **外れたものだけがモデルに回る。** KB を外れると、世界照合モデルが根拠を集めます（Wikipedia と OpenAlex は常に、加えて Web 検索の MCP ツールがつながっていればそれも）。そして、その根拠に照らして主張を判定します。根拠が何も出てこなければ、モデルは自分の知識にフォールバックします。

モデルの判定は、そのつどローカル KB に沈殿します。似た主張の次回の照合は KB ヒットになるので、KB は自分の分野に合わせて育ち、使うほど照合は速く・安くなります。

ノートに保存された verdict と KB のキャッシュは別物です。ノートから verdict を消しても KB は変わりませんし、KB のエントリを削除しても、すでにノートに刻まれた verdict は消えません。

## 自動照合 <Badge type="tip" text="v0.13.3 (2026-06-02) で追加" />

既定では、照合は頼んだときだけ走ります。新しいナレッジができた時点で照合させたい場合は、**設定** → **AI** を開き、**世界照合** セクションの **自動で世界照合する** をオンにします（既定はオフ）。

オンにすると、新しく作られた知見・洞察がバックグラウンドで 1 件ずつ照合されます。トーストは出ず、静かに進みます。対象は一度も照合されたことのない項目だけで、しかも先に KB を見るので、モデルが呼ばれるのはまだ知られていない主張に限られます。

## 世界照合に使うモデル

同じ **設定** → **AI** の **世界照合** セクションで、専用の **世界モデル照合用モデル** を選べます。空のまま（**チャットモデルと同じ**）にしておくと、照合はチャットモデルを使い、それも空ならデフォルトモデルにフォールバックします。ふつうは、ここを別に設定する必要はありません。

モデルの登録や他の割り当てについては [AI のセットアップ](/ja/ai-setup)を参照してください。

## 再照合と verdict の削除 <Badge type="tip" text="v0.13.5 (2026-06-03) で追加" />

- **再照合**: もう一度 **世界照合** を押します。新しい結果が古いものを置き換えます。
- **削除**: 項目下部の **世界照合 詳細** セクションで **照合結果を消す** を押すと、その項目に保存された verdict と出典が消えます。間違った判定や壊れたリンクが焼き付いてしまったときに使います。一覧では、行を選んで件数付きの **照合を消す (n)** を押せば、まとめて剥がせます。

::: tip
手で消した項目は、自動照合が意図的に飛ばします。消す操作は「これを自動で付け直さないでほしい」という合図になります。新しい verdict が欲しくなったら、自分で **世界照合** を押してください。
:::

## AI の回答に渡す範囲 <Badge type="tip" text="v0.16.8 (2026-07-02) で追加" />

AI に質問するときにも、これと地続きの仕組みがあります。AI チャットパネルと ⌘K Composer にある **渡す範囲** チップで、回答が何を根拠にするかを選びます — **外部参照**（Web 検索を必須にする）、**内部参照**（引用したもの＋蓄積した知識の横断検索）、**ノート内参照**（このノートで引用したものだけ。既定）。詳しい内訳と、**外部参照** が Web に届くために何が必要かは[チャットと Ask (Cmd+K)](/ja/ai-chat-and-ask#choosing-what-grounds-the-answer)を参照してください。

## 照合データを管理する

**設定** → **照合データ** は、世界照合が突き合わせる知識ベースの中身を見たり、間引いたりする場所です。最初は空で、照合を実行するほど育ちます。

![設定の照合データタブ。キャッシュされた KB エントリが verdict のフィルタとともに並んでいる](/screenshots/grounding-data-tab.png)

- ヘッダーにエントリ件数が出ます。verdict のフィルタチップや **KB を検索...** の欄で一覧を絞れます。
- 各エントリにはバッジが付きます。**seed** はアプリに同梱された手キュレーションのエントリ（UI からは削除できません）、**model** はモデル判定から沈殿したエントリです。バッジにカーソルを合わせると、どのモデルが作ったものかが分かります。
- 個別のキャッシュエントリはゴミ箱ボタンで削除できます。件数付きの **沈殿エントリを一括削除 (n)** を押せば、モデル由来のキャッシュエントリをまとめて消せます。どちらの場合も seed エントリは残ります。

エントリを削除しても、影響するのは以後の照合だけです。もう信用できない判定を追い出し、次の **世界照合** で新しい根拠から導き直させるための操作です。
