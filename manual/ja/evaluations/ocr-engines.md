# 取得型のモデルなら、今の OCR で読めない手書きまで読めるか <Badge type="info" text="2026-11-18 測定 · v0.141" />

**確かめたこと。** Graphium は画像の文字を tesseract.js で読んでいます。これを、取得して使う小さなモデルや OS 標準の OCR に替えると、手書きまで読めるようになるのでしょうか。精度は上がるのでしょうか。

**ひとことで。** 今の OCR（tesseract.js）は、手書きの 160 句を 1 句も拾えませんでした。約 22〜180 MB の検出・認識モデル（PP-OCR）は、写真と表を大きく、活字を少し改善しますが、手書きは日付と数値までで、文は読めません。確かめた手書きの句の多くを拾えたのは（正解は私の下書きで、ノートの持ち主の確認はまだです）、macOS 標準の Vision と、GB 級の OCR 専用の視覚言語モデル（glm-ocr）でした。**この測定では、既定の OCR はまだ変えていません。** どれを載せるかは未決定で、Windows は測っておらず、glm-ocr のライセンスと配布形態も確かめていません。

## 測り方

| | |
|---|---|
| 機材 | Apple M1 Max、macOS 27.2。時間はこの機材の値です |
| エンジン | tesseract.js 7（今と同じ。jpn+eng、`4.0.0_best_int`）。PP-OCRv5（mobile 約 22 MB、server 約 180 MB）と PP-OCRv6 の日本語（small 約 31 MB、medium は検出と認識で約 139 MB）を、rapidocr 3.10.0 と onnxruntime 1.32.0 で動かした。Apple Vision（`VNRecognizeTextRequest`、accurate、ja-JP と en-US。macOS のみで、取得するものはない） |
| 視覚言語モデル | 同じ日に ollama 0.40.6 で動かした。長辺 2000px に縮めて渡し、temperature は 0。glm-ocr（2.7 GB）、deepseek-ocr（6.7 GB）、gemma3:4b（3.4 GB）、qwen3-vl:4b（3.3 GB） |
| 合成データ | 測定用に作った 16 枚。活字・小さい字・表・暗い画面・縦書き・写真風の劣化で、題材はパン作り。正解は全文 |
| 手書き | 利用者から提供された 7 枚。実験ノート 6 ページとメモ 1 枚を iPhone で撮った写真（3024×4032）で、向きだけ直した。正解は全文ではなく、縮小画像で確信を持って読めた 160 句。**正解の下書きは、私が AI の補助を受けて作りました。持ち主の確認はまだです** |
| 採点（合成） | 文字誤り率（CER）。NFKC で正規化し、空白を除いた。読み順を無視した誤り（文字の多重集合の F1）も見た |
| 採点（手書き） | 句が出力のどこかに出ているか（句にいちばん合う部分文字列との編集距離 ÷ 句の長さ）。0.2 以下を「当たり」とした |

手書きの中身は、ここには載せません。そこに書かれている文や数値も、引用しません。

## 分かったこと

- **縦書きと傾いた写真での PP-OCR の誤りは、実行スクリプトの並べ順が原因でした。** 列を左から読み、傾いた行を独自に束ねる処理です。文字そのものは読めていて、順序を無視した誤りは、縦書きで 0.04〜0.06、写真風で 0.02 以下でした。
- **Vision と glm-ocr は、得意なところが逆でした。** 日本語の文は Vision が上（70 % 対 52 %）、数値・単位（86 % 対 50 %）と完全一致（54 % 対 38 %）は glm-ocr が上です。全体は 69 % で並びました。
- **glm-ocr には、行を飛ばして、別の語で文を閉じてしまう誤りがありました。** たとえば、2 行にまたがる文の後半が落ちて、別の語で終わります。文字化けではなく読める文になるので、気づきにくい誤りです。
- **汎用の小型モデル（gemma3:4b）は、書かれていない語と数値を作りました。** OCR には向きません。
- **PP-OCRv5 の ch モデルは、簡体字が混ざります。**
- PP-OCR は、手書きの日付と数値は拾いますが、続け字の日本語の句はほとんど拾えません。tesseract.js は、手書きから意味のある文字を出せませんでした。

## 限界

- 手書きは 1 人の筆跡・7 枚です。正解は、読みやすい句に偏っています。
- 正解の下書きは私が AI の補助で作ったもので、持ち主の確認はまだです。
- 合成データは、実写より易しいです。縦書きと暗い画面は、1 枚ずつです。
- 時間は M1 Max だけで測りました。Windows は測っていません。Vision は macOS にしかありません。
- 視覚言語モデルには、長辺 2000px に縮めた画像を渡しました。別の大きさでは結果が変わるかもしれません。
- 接続済みの AI は測っていません。
- glm-ocr のライセンスと配布形態（ONNX 化できるか、ollama なしで動かせるか）は、確かめていません。PP-OCRv6 のモデルの出どころとライセンスも、まだ控えていません。

## 決めたこと

- まだ何も変えていません。Graphium の OCR は今も tesseract.js のままです。どのエンジンを、どの環境に足すかは、決めていません。
