# 研究室の GPU 1 枚で動かす gemma は、API で測った品質を保てるか <Badge type="info" text="2026-11-20 測定 · v0.129" />

**確かめたこと。** 研究室のワークステーションに AI のモデルを載せて、Graphium から使っています。ノートの中身を研究室の外に出さずに、AI 機能を使うためです。最初は `gpt-oss-120b` を載せていましたが、[前回の測定](/ja/evaluations/cloud-and-local-models-by-feature)で API 経由の `gemma-4-31B-it` の方が多くの作業で良かったので、`gemma-4-31B-it` に替えました。

ただ、前回 gemma が良かったのは API 経由で測った値です。ワークステーションに載せたのは、4 ビットに縮めた版（`gemma-4-31b-qat`）です。同じ 4 ビット版を Mac で動かしたときは、251 回のうち 57 回が 10 分に収まりませんでした。ワークステーションの GPU なら、API で測った品質と速さがどこまで出るのかを確かめました。

**ひとことで。** ワークステーションの gemma は、45 個の指標のうち 21 個で `gpt-oss-120b`（API）を上回りました。下回ったのは 11 個です。API 経由の gemma とは、ほぼ同じでした（上 13・下 15・同じくらい 17）。時間切れは 251 回のうち 2 回だけでした。

- **上がった作業**: チャットの回答、点検、翻訳、名寄せ、要約で会議に無いことを書く量、清書の訂正
- **下がった作業**: 世界照合（一般的な知識に照らして正しいか）、トピックの改訂、論文から工程を取り出す作業。清書では、直してはいけない発言を直す率が上がった
- **遅さ**: 1 回の呼び出しは中央値 74 秒。同時に 2 本流したので、1 本ずつ流すより長くなっています

この結果から、ワークステーションの既定は `gemma-4-31B-it` のままにしました。世界照合を多く使う場合は、ほかのモデルを選ぶ方が合います。

## 分かったこと

- **4 ビットに縮めても、ほとんどの作業で品質は API 経由と並びました。** Mac で落ちた点検・論文からの工程・清書が戻ったので、Mac の低い値の多くは、時間切れによるものだったと考えられます。
- **世界照合だけは、Mac と同じ .40 に下がりました。** 誤った判定が増えたのではありません。検索はしたものの「根拠が見つからない」として判定を出さない件が、40 件のうち 22 件ありました（API 経由の gemma は 8 件）。4 ビットにしたためなのか、検索の結果がその日ごとに違うためなのかは、切り分けていません。
- **清書は、直す量も、直しすぎも増えました。** 聞き違いを直した率は .27 から .47 に上がりました。一方で、直してはいけない発言を変えた率も .04 から .33 に上がっています。
- **長い作業は数分かかります。** 知見の一般化や清書は、1 回 4 分を超えます。チャットの回答は 15 秒ほどです。

## 限界

- 1 回だけの測定です。件数の少ない作業（要約 6・清書 6・論文 7・計画 10）は、区間が広くなります。
- 採点者の 1 人が、保存先の一覧を見たときに、ほかの束の採点結果を目にしたと報告しました。その結果は採点に使っていないとのことです。
- 測定は 3 回止まり、続きから流し直しました。止まったあいだに失敗した 2 回は、測定側の失敗として流し直しています。
- ワークステーションの `gpt-oss-120b` は、このベンチでは測っていません。表の `gpt-oss-120b` は API 経由の値です。同じワークステーションで短い作業の時間を比べたときは、gemma の方がおよそ 2 倍遅くなりました。
- 入力は、架空の料理の記録です。研究のノートでは結果が変わるかもしれません。
