# よくある質問

よく届く質問——特にナレッジ層の「なんでそうなったの？」——に正面から答えるページです。Graphium の設計方針は、ここで出会う数字をすべて **自分で決めたコスト** か **手持ちのコーパスから実測された値** のどちらかにすること。隠れた品質フィルターは置きません。各質問をクリックすると答えが開きます。

::: details 洞察があまり生成されないのはなぜ？

[洞察](/ja/knowledge-layer)は抽象化です。モデルが知見を読み、元の文脈の外でも通用する規則（「可搬性テスト」）を取り出そうとします。あまり出ないときは、次の順で確認してみてください。

1. **知見は収束していますか？** 一回きりの事実の寄せ集めには、抽出できる繰り返しのパターンがありません。モデルには *無理にひねり出すより空のリストを返すほうがよい* と明示的に指示してあるので、コーパスが若い・散らばっているうちは 0 件が正直な答えということもあります。複数の知見が同じ規則の周りに集まりはじめると、洞察が生まれます。
2. **抽象化を担うモデルはどれですか？** 洞察の生成には[設定](/ja/settings)の **洞察の発見** セクションの **洞察モデル** が使われます（未指定ならチャットモデル、さらにデフォルトモデルへとフォールバック）。抽象化はパイプラインの中でいちばん難しいステップで、小さなローカルモデルは、強いモデルなら見つけるパターンでも空のリストや知見の言い換えを返しがちです。ここには最上位級のモデル（例: Claude Opus / Claude Sonnet）をおすすめします——「推論対応」や大きさだけでは足りないことがあります。目安の表は [AI のセットアップ](/ja/ai-setup)にあります。洞察が少ないと感じたら、強いモデルを割り当てて発見をもう一度実行してみてください——同じコーパスで、変数はモデルだけ。強いモデルでも何も出なければ、限界はソフトウェアではなく素材の側にあります。
3. **新規ではなく「支持追加」になっていませんか？** 既存の洞察と embedding が似ている候補は、自動でそのまま取り込まれるわけではありません——embedding の一致は「候補」を絞り込むだけで、本当に同じ主張か・矛盾しているか・実は別物かは AI が判定します。同じなら支持追加（結果パネルに *支持追加* として件数が出ます）、矛盾なら両方の洞察をそのまま残し点検タブに矛盾として出ます、実は別物なら新規ページになります。支持追加が出ているなら発見は機能しています——洞察が増える代わりに、手持ちの洞察が強くなっているだけです。
4. **本当に全部見終わっていますか？** スキャンは実測カバレッジを **視野 n/m 件** として報告します——手持ちの知見のうち、少なくとも一度は視野に入った数です。取り込み時のスキャンには予算があるので（下の質問を参照）、大きなコーパスは設計上、一度の取り込みでは一部しか見ません。全体をくまなく見たいときは、[設定](/ja/settings) → **ナレッジ管理** の **知見をまたぐ洞察を発見** を実行してください。実行前に全件を視野に入れるのに必要な LLM 呼び出し回数の実測値が表示され、終了後には到達したカバレッジが報告されます。

:::

::: details Graphium がこっそり件数を制限していませんか？

していません。品質を理由に黙って捨てる処理はありません。モデルの確信度（confidence）は記録・表示されるだけで、候補の破棄には使われませんし、スキャンが作るべき件数の下限・上限もありません。知見も同じで、抽出器には「持ち運べる主張はすべて収穫する。固定の上限はない」と指示してあります。

存在する数字は次の 3 種類に分かれ、それぞれ理由を確認できます。

| 数字 | 何か | なぜあるか |
|---|---|---|
| 取り込み時のスキャン回数（既定 3） | [設定](/ja/settings) → AI にあるユーザー設定。1 回のスキャン = 知見のクラスタ 1 つに対する LLM 呼び出し 1 回 | **コストの制御——決めるのはあなたです。** 0 にすれば取り込み時のスキャンを止められます。結果には必ず実測カバレッジが表示されるので、どこまで見た・見ていないが分かります |
| 全件カバーに必要な回数 | **知見をまたぐ洞察を発見** の確認ダイアログに表示 | **設定値ではなく実測値。** 知見の分布から計算され、すべての知見が一度は視野に入るまでスキャンが回ります |
| 1 回の呼び出しは知見 50 件まで・本文は先頭のみ | 内部のスライスサイズ | **コンテキスト長の保護** ——これ以上入れるとモデルの入力から静かに溢れます |
| チャットに渡す文脈の予算（ナレッジ 2000 字・ノート/素材 1600 字・1 断片 700 字） | AI チャットが根拠として読む断片の文字数の上限 | **コンテキスト長の保護** ——「ここまでしか根拠に使わない」という品質の線引きではなく、モデルの入力から静かに溢れないための予算です。件数の上限ではありません |
| 検索結果の突き合わせに渡す候補 20 件 | 語彙検索と埋め込み検索の順位を融合するときの候補プール | **組み立てコストの蓋です。** 検索そのものは両方とも全件を見ています。ここを絞っても取りこぼしは増えず、最終的に渡す断片は上の文字数の予算が決めます |
| 埋め込み検索に渡す質問文は 1000 字まで | 埋め込みモデルへの入力の切り詰め | **物理的な制約です** —— multilingual-e5-large の入力上限は 512 トークンで、長い引用や貼り付けが混ざったときに検索ごと失敗しないよう先頭を残して切ります |
| 重複判定のしきい値（embedding 類似度） | 既存の洞察との「一致候補」を絞り込む（最終判定ではない） | **これは候補探しであって、判定ではありません。** embedding は否定や向きの違い（「下がる」と「上がる」）に鈍く、そのまま重複扱いにすると矛盾する洞察が支持として統合されてしまいます。絞り込んだ候補ペアは AI が同じ / 矛盾 / 別物を判定してから振り分けます——同じなら支持追加（一致した洞察が新しい裏づけの知見を得る）、矛盾なら両方の洞察をそのまま残し点検タブに `矛盾` として出す（両方を開いて見比べられる）、別物なら新規ページ。embedding モデル未設定のときは候補探し自体が素通りし、全部新規扱いです |
| 長い資料は 4,000 字の窓に分けて読む（重なり 400 字） | トピック段が資料を読む前に分ける処理 | **コンテキスト長の保護で、読む範囲を狭める上限ではありません。** 窓 1 枚に収まる資料は今までどおり 1 回で読みます。長い資料は文の切れ目に寄せて分け、**すべての窓を読む**ので、どこかから先が読まれないことはありません。窓ごとに振り分け・改訂するため、長い資料は長さに比例して AI 呼び出しが増えます——進捗には窓の枚数が出て（**32 枚中 5 枚目**）、**停止**は次の窓の境目で効きます。窓が増えればトピックも増えることがありますが、これは粒度の話で、絞り込みではありません。似たトピックは裏で勝手に統合せず、トピックを整理・点検タブが拾います |
| トピックの振り分け | 取り込んだ資料がどの既存トピックを改訂し、どの新規トピックを作るかを決める | **しきい値は一切ありません。** 資料の本文（長い資料は窓 1 枚ずつ）と既存トピックの一覧（タイトル＋定義の 1 文）を AI に渡し、「同じ概念か新規か」を AI 自身に判断させます——embedding 類似度もタイトルの正規化一致も使いません。すり抜けた重複はトピックを整理・点検タブが後から拾います |
| トピックを資料から作り直すときの呼び出し回数 | 「資料から作り直す」（トピックページ自身の再生成、手入れの旧形式トピックまとめ、資料の一部が見つからない項目の手当てのいずれも）の確認ダイアログに表示 | **実測であり、決め打ちではありません** — そのトピックが引用する資料 1 件につき 1 回で、実行前に計算して見せます。自動では動かず、必ずボタンを押した人が起動します |
| 1 回の呼び出しで候補 0〜8 件・洞察 1 件の関係は 3 本まで | プロンプト側のレンジ | **出力の暴走ガード** です。ナレッジの上限ではありません——スキャンを重ねれば見つかったものは追加されていきます |
| スキャンには知見が 2 件以上必要 | 実行の前提条件 | 知見をまたぐパターンには、またぐ相手が要ります。知見が 1 件では、まだ突き合わせる対象がありません |
| 実在しないソース ID の候補は破棄 | パーサのガード | **ハルシネーション防御** ——存在しない知見を引用する候補は、壊れた参照つきで保存する代わりに破棄されます |
| 点検の「古い項目」「冗長」に日数・重なり率のしきい値は無い | [ナレッジの手入れ](/ja/knowledge-layer)の点検タブのロジック | **判定であって、しきい値ではありません。** 「古い項目」は、後から作られた具体的な知見・ノートに追い越されていると AI が指摘できたときだけ検出されます——経過日数だけでは検出されません。「冗長」は、表現や粒度の違いを超えて同じ主張を指しているときだけ検出されます——主題が重なっているだけでは検出されません |
| フル点検が AI に渡すページの中身を絞っている | フル点検（AI 解析）が問題・[次に調べること](/ja/knowledge-layer#次に調べること)を判定する前の入力の組み立て | **数値のしきい値ではなく、種類で絞っています。** 生成を止めた旧種別の「要約」は渡さず、知見はタイトルだけ渡します（知見のタイトルは命題そのものなので、本文のプレビューは重複でした）。トピック・問答（Q&A）・洞察は今までどおり本文のプレビューつきです。実データ規模（約 900 ページ）で LLM への入力は約 15.7 万トークンから約 6 万トークンに減り、131k のモデルに収まるようになりました |
| 「次に調べること」の件数に上限は無い | フル点検（AI 解析）が挙げる[次に調べる価値のある問い](/ja/knowledge-layer#次に調べること) | **質で絞っていて、件数では絞っていません。** 答えが分かれば既存のページの記述が変わる・新しいページが要るようになる問いだけを挙げるよう求めていて、一般論やすでにページに書いてあることの言い換えは対象外です。追加の AI 呼び出しはありません——フル点検の 1 回の呼び出しに相乗りしています |
| [出典照合](/ja/ai-grounding#出典照合-出典に実際に書いてあるか)自体は新しい数字を持たない | 実行前に表示される判定回数 | **設定値ではなく実測値です**——関わる出典の数で、上の洞察発見の呼び出し回数と同じ考え方で数えます。出典を取り出せなかった分は判定せずに飛ばすので、実際の回数は表示より少なくなることがあります |
| 出典照合が読み直す原文に上限は無い | 引用元のノート・PDF・Word ファイル・URL を照合のために読み直す処理 | **資料の全文を読みます**——出典照合が独自に足す上限はありません。PDF も全文で、トピック段が窓に分けて読むのと同じ範囲です |
| 1 回の呼び出しで全文を渡す経路だけ、PDF の本文を 80,000 字で打ち切る | 知見の抽出・PROV 取り込み・複数の資料からページを作り直す処理 | **窓に分けない経路のためのコンテキスト長の保護です。** おおよそ 60〜90 ページぶんで、この 3 つには「どこまで読んだか」を伝えています。トピック・出典照合・検索インデックスには上限はなく、資料の全文を読みます |
| 自動で出典照合するは既定オフで、動いたときだけ AI を呼ぶ | 設定の[自動で出典照合する](/ja/ai-grounding#自動で出典照合する)トグル | **オプトインであって、裏で常時動く既定値ではありません。** オンにすると新規・更新された知見とトピックを 1 件ずつ・出典 1 件ごとに AI を呼んで照合します——オンにしない限り一切動きません |

この表で説明のつかない「隠れフィルターのような挙動」を見つけたら、それはバグです。[Issue で教えてください](https://github.com/kumagallium/Graphium/issues)。

::: details Graphium とモデル、どちらの問題か切り分けるには？

対照実験を 1 つ回します。[設定](/ja/settings) → **ナレッジ管理** → **知見をまたぐ洞察を発見** を実行し、結果の行——*作成*・*支持追加*・*視野 n/m 件*——を控えてください。カバレッジが全件に達し、支持追加はあるのに新規がないなら、パイプラインは全部を見た上で「いまあるパターンは既存の洞察で説明済み」と判断しています。次に **洞察モデル** に強いモデルを割り当てて、もう一度実行します。強いモデルでだけ洞察が生まれるなら、ボトルネックはモデルでした。それでも出なければ、知見にはまだ新しい繰り返しのパターンが育っていません——ノートを書き足して、収束を待つのが近道です。

:::

::: details 知見と洞察の違いは？

**知見**はノートや資料から取り出した命題 1 つ。**洞察**は知見から取り出した、他の分野でも通じる関係の型です。ノート → 知見 → 洞察という砂時計のくびれを成しています。全体像は[ナレッジ層](/ja/knowledge-layer)のページをどうぞ。

知見・洞察は、元の資料から直接作られ常にオンのトピックの上に乗る、Graphium 独自の拡張です。**設定 → AI** の **知見を使う** で丸ごとオフにできます（初めて使うときは既定オフ、以前から使っている場合はオン）。オフにすると取り込み時の知見抽出が止まり（トピック段は同じ資料テキストから引き続き走ります）、洞察は知見から作るため洞察も一緒にオフになります。すでに作ったページは消えず、1 件でも残っていれば表示され続けます。

:::
