# AI のセットアップ

Graphium の AI は任意の機能です。AI がなくても、アプリはノートエディタとして使えます。モデルを 1 つも登録していないあいだは、AI 系の操作（チャット、Composer、ナレッジ生成、素材に対する AI 操作）はすべて隠れています。そのため、設定を促されることもありません。

このページでは、何もない状態からモデルが動くところまでを案内します。内容は次のとおりです。

- AI がどこで動くか
- モデルの追加方法
- API キーの保存場所
- モデルの割り当てが、それぞれ何に効くか
- AI にかかる費用の確かめ方

## AI が動く場所

AI 機能には、モデルのプロバイダーと通信する小さなローカルバックエンドが必要です。このバックエンドは[デスクトップアプリ](/ja/desktop-app)に同梱されていて、自動で起動します。別にインストールするものはありません。

ブラウザ版は、バックエンドを持たないエディタのプレビューです。AI 系の操作は隠れたままで、AI タブには代わりに **デスクトップ版を入手** ボタン付きの案内が出ます。

間に Graphium のクラウドサービスが入ることはありません。バックエンドは自分のマシンで動き、設定したプロバイダーへ直接リクエストを送ります。

## AI タブ

[設定](/ja/settings)を開き、**AI** タブを選びます。このページで扱う内容は、最後に説明する使用量タブを除いて、すべてここにあります。

![登録済みモデルとモデルの割り当てが並ぶ AI タブ](/screenshots/settings-ai-models.png)

::: info 接続の確認
デスクトップアプリを起動した直後は、バックエンドが立ち上がるまで数秒かかります。その間、サイドバーの **ナレッジ** タブには **バックエンドを起動しています…** と表示されます。**設定** の隣の点は灰色のままです。AI が使える状態になると、点は緑に変わります。バックエンドが起動しなかった場合は、同じタブに **バックエンドを再起動** ボタンが出ます。

AI タブは、開くたびにバックエンドを確認します。部品ごとの **接続状態** パネルは **ナレッジ管理** タブにあります。バックエンドが止まっているとき、デスクトップアプリではそこにも **バックエンドを再起動** ボタンが出ます。**ログを表示** を押すと、何が起きたかを確認できます。

アプリの利用中にバックエンドが止まったときは、ウィンドウの上部にバナーが出ます。文言は **AI バックエンドが停止しました。AI 機能を使うには再起動が必要です。** です。同じ **バックエンドを再起動** と **ログを表示** のボタンから、設定を開かずに復帰できます。
:::

## モデルを追加する

::: tip どのプロバイダーを選ぶか
- **GitHub Copilot をすでに契約している** なら、**設定 → AI** の **GitHub アカウントで使う** の **接続する** を押してください。API キーは要りません。利用量は今のプランの枠に数えられ、MCP ツール（web 検索など）もそのまま動きます。Graphium の AI を一通り使うには、いちばん手軽な方法です。
- **まず無料で試したい** なら、**API キーでつなぐ（クラウドのサービス）** を開き、**無料枠のあるものだけ表示** にチェックを入れてください。無料枠は接続先ごとに数え方も量も大きく違います。[AI の使用量と無料枠の目安](/ja/ai-usage-limits)で比べてから選んでください。
- **API キーがある** なら、キーでつなぐどのプロバイダーでも動きます。下のモデルの割り当てで、複数のモデルを組み合わせられます。
:::

### どこにつなぐかを選ぶ <Badge type="tip" text="v0.95.8 (2026-10-26) で追加" /> {#choose-where-to-connect}

**登録済みモデル** の下にある **モデルを追加** を押すと、最初に **どこにつなぎますか？** と聞かれます。モデルが 1 つも登録されていないときは、**設定 → AI** を開いた時点で、この選択が出ています。

| 選ぶもの | どうなるか |
|---|---|
| **登録済みの接続先にモデルを足す** | すでに使っている接続先（同じキー）に、別のモデルを足す。登録済みのモデルがあるときだけ出る |
| **GitHub アカウントで使う** | GitHub Copilot に、ボタン 1 つでつなぐ（[下](#github-copilot-をボタン-1-つでつなぐ)）。デスクトップ版だけ |
| **API キーでつなぐ（クラウドのサービス）** | Anthropic・Cloudflare・Google・Mistral・OpenAI・OpenRouter・さくらの AI Engine から選び、キーを貼ってつなぐ（[下](#free-tier-services)） |
| **このパソコンで動かす** | LM Studio や Ollama で動かしているモデルにつなぐ。キーは要らない |
| **URL を指定してつなぐ（社内・研究室のサーバーなど）** | 会社や研究室で動かしている LLM サーバー（OpenAI 互換など）や、一覧に無いサービス向け。OpenAI 互換のサーバーの URL を自分で入れる（[下](#connect-with-an-address)） |

接続先を選ぶと、必要な欄だけが出ます。キーを貼ると、Graphium が自動で接続を確かめます。そして、使えるモデルの中から、チャットに使えるふだん使いのモデルを選んでおきます。**追加する** を押せば登録は終わりです。

URL・モデル・表示名を変えたいときだけ、**詳しい設定** を開いてください。**つなぎ先を選び直す** を押すと、接続先の選択に戻れます。

![Connect to OpenAI の画面。伏せ字の API key、「Connected. Using gpt-5.6-luna (4 to choose from).」、開いた Advanced settings（API Base URL・Model・Display name）と Add ボタンが見える。](/screenshots/ai-connect-key-form.png)

### URL を指定してつなぐ {#connect-with-an-address}

**URL を指定してつなぐ（社内・研究室のサーバーなど）** は、OpenAI の API と同じ形で通信するサーバー（vLLM・llama.cpp・LiteLLM・Groq など）向けです。Anthropic・OpenAI・Google は **API キーでつなぐ** にあります。URL は **詳しい設定** で変えられます。GitHub Copilot は **GitHub アカウントで使う** にあります。そのため、この入力欄ではプロバイダーを選びません。

手順は次のとおりです。

1. **API Base URL** を入れます。たいてい `/v1` で終わります。
2. サーバーが求める場合だけ、**API キー** も入れます。
3. **利用可能なモデルを取得** を押し、一覧から 1 つ選びます。**または手動でモデル ID を入力** も使えます。
4. 必要なら **表示名** を設定し、**追加** を押します。

最初に登録したモデルがデフォルトになり、アプリ全体に AI 機能が現れます。表示名は重ねられません。すでにあるモデルと同じ名前で追加したり改名したりしようとすると、その場に理由が出て、保存されません。

**国内のクラウドの例:** データを国内に置きたい場合の例として、さくらインターネットの「さくらの AI Engine」は **API キーでつなぐ** の一覧にあります。URL の `https://api.ai.sakura.ad.jp/v1` は自動で入ります。基盤モデル無償プランは月 3,000 リクエストまで無料です。超えると制限がかかるだけで、課金は始まりません。料金と条件は、公式の [料金表](https://ai.sakura.ad.jp/sakura-ai/ai-engine/) で確認してください。

> 注：Graphium の開発者はさくらインターネットの社員です。この記載は個人の開発プロジェクトとしての情報提供で、同社の依頼や対価によるものではありません。ほかの OpenAI 互換の接続先も同じように使えます。

**手元のモデル（Ollama など）:** 4〜8B 程度の小さなモデルは、要約はこなせます。ただ、ナレッジ化では、元のノートに無い数値や主張を作ることがあります（2026-10 の手元の計測。[検証の記録](/ja/evaluations/local-models-as-default) を参照）。ナレッジ化に使うなら、クラウドのモデルか、大きめのモデルをお勧めします。Ollama の既定の文脈長（一度に読める長さ）が大きすぎると、メモリを大量に使います。`OLLAMA_CONTEXT_LENGTH=32768` 程度を指定してください。

**LM Studio:** 手元のモデルが一度に扱えるのは、読み込むときに決める **コンテキスト長** までです。**Max Concurrent Predictions** が 2 以上だと、その枠を複数の処理で分け合います。

- 枠が足りなくなると、LM Studio は「Channel Error」としか返しません。Graphium は代わりに「このパソコンで動くモデルの、一度に扱える量が足りませんでした」と出し、この 2 つの設定を案内します。
- 音声ノートの清書では、Max Concurrent Predictions を 1、コンテキスト長を 16,384 以上にします。長い会議の要約なら 65,536 にします。そのあと、モデルを取り出してから読み込み直してください。新しい値は、読み込み直すまで効きません。
- 音声ノートの **清書する**・**要約する** を押すと、Graphium は先に、LM Studio が読み込み中のコンテキスト長を問い合わせます。足りなそうなときは知らせるので、**このまま実行** か **やめる** を選べます。
- モデルが読み込まれていない、ほかのアプリが別のモデルを読み込ませた、LM Studio が動いていない、といったときは、LM Studio は「Bad Request」などとしか返しません。Graphium は代わりに「このパソコンで動くモデルが応答しませんでした」と出し、モデルが読み込まれているかを確かめるよう案内します。

**答える前に考えるモデル（Qwen 3・Gemma 4 など）:** 音声ノートの清書では、書くことよりも考えることに、ずっと多くの時間を使うことがあります。手元の試しでは、Qwen 3.6 のモデルが、書く量の約 9 倍を考えるのに使い、1 回分に約 5 分かかりました。清書に長い考えは要りません。

LM Studio で確実に止めるには、モデルのプロンプトテンプレートを使います。モデルの設定の **Prompt Template**（Jinja）の 1 行目に `{%- set enable_thinking = false %}` を足し、モデルを読み込み直してください。この方法で止められるかは、モデルのテンプレート次第です。清書の実行中は、ブロックに、何回分が終わったかが出ます。1 回目が終わったあとは、残り時間の目安も出ます。

### GitHub Copilot をボタン 1 つでつなぐ <Badge type="tip" text="v0.92.2 (2026-10-21) で追加" />

GitHub Copilot をつなぐいちばん簡単な方法は、**GitHub アカウントで使う** の **接続する** ボタンです。押すと、Graphium が次の順に進めます。

1. パソコンに Copilot の部品がなければ、取得します。
2. ブラウザで GitHub を開き、承認を待ちます。
3. 接続を確かめたら、モデルを登録します。

すでにサインイン済みなら、承認は要りません。ブラウザが開かないときは **コードで承認する** を押し、表示された 8 桁のコードをコピーして、GitHub で入力してください。GitHub アカウントで Copilot が有効になっていない場合は、**Copilot を有効にする** が出て、GitHub の Copilot 設定ページへ案内します。プロンプトは、Copilot プランの利用枠を消費します。

![どこにつなぎますか？の選択。GitHub アカウントで使う（接続する）・API キーでつなぐ・このパソコンで動かす・URL を指定してつなぐが並ぶ](/screenshots/settings-ai-connect.png)

::: warning 研究データを扱う前に
AI に渡すノート・資料・チャットの内容は、GitHub Copilot に送られます。**個人プラン（Copilot Free / Pro / Pro+ / Max）では、2026 年 4 月 24 日から、設定で止めない限り GitHub が AI の学習に使うことがあります**。Copilot Business / Enterprise は対象外です。

未公開のデータを扱うなら、GitHub の右上のプロフィール画像 → **Copilot settings** で、**Allow GitHub to use my data for AI model training** を **Disabled** にしてください。ボタンの下の **GitHub の設定で止める** からも開けます。詳しくは GitHub の[個人向け Copilot ポリシーの管理](https://docs.github.com/ja/copilot/how-tos/manage-your-account/managing-copilot-policies-as-an-individual-subscriber)を参照してください。
:::

**学生・教員の方へ:** 認証を受けた学生は Copilot Student を、教員・研究者は Copilot Pro を、無料で使える場合があります。資格は毎月見直されます。教育向けの無料版も個人プランの扱いです。学習への利用は、上の警告のとおり設定で止めてください。条件は [GitHub の公式ページ](https://docs.github.com/copilot/how-tos/manage-your-account/get-free-access-to-copilot-pro) で確認できます。

**ログインが切れたら:** 時間がたつと、GitHub のログインが切れることがあります。そのときは **設定 → AI** の上部に「GitHub Copilot のログインが切れています」と出ます。**もう一度ログイン** を押してください。登録済みの Copilot のモデルの行にある **GitHub にもう一度ログイン** からも、同じ操作ができます。ブラウザで承認するだけで、モデルの登録はそのまま使えます。

**ターミナルが得意な方へ:** GitHub Copilot CLI でサインイン済みなら、**接続する** はそのサインインを使うので、承認は要りません。サインインするには、`npm install -g @github/copilot` を実行し、そのあとターミナルで `copilot` を一度実行します。

- Copilot の別のモデルを足すときは、**登録済みの接続先にモデルを足す** で GitHub Copilot を選び、**利用可能なモデルを取得** を押します。
- あとから GitHub アカウントを切り替えるには、**設定 → AI** の Copilot モデルの **GitHub にもう一度ログイン** を押し、ブラウザで別のアカウントを選びます。

以前のバージョンには、Claude Pro/Max プランで AI を動かす **Claude (Subscription · Claude Code)** プロバイダーがありました。Anthropic の規約が、サードパーティアプリからのサブスクリプション認証の利用を認めていないため、廃止しています。

この方法で登録したモデルは、更新後の最初の起動で、一覧から取り除かれます。別のプロバイダーを登録し直してください。Anthropic の API キーは、これまでどおり使えます。「API キーなしで使う」方法は、上の GitHub Copilot プロバイダーが引き継いでいます。

### API キーでつなぐ（無料枠のあるサービスを含む） <Badge type="tip" text="v0.94.8 (2026-10-22) で追加" /> {#free-tier-services}

**どこにつなぎますか？** の **API キーでつなぐ（クラウドのサービス）** を開くと、キーでつなげるクラウドのサービスが、名前の順に並びます。項目は、どのサービスも同じです。無料枠のあるものも無いものも同じ一覧に並び、どれかを勧めることはしていません。

- 一番上の **無料枠のあるものだけ表示** にチェックを入れると、無料枠のあるサービスだけが残ります。
- 各サービスには、次の 3 つが並びます。
  - **無料枠**: Graphium で、論文なら月に何本、チャットなら何往復使えるかの目安。無料枠の無いサービスは「無料枠なし（使った分だけ請求）」
  - **学習**: 送った内容が AI の学習に使われるか。使うサービスは、この行が注意の色になります。
  - **登録**: 登録に要るもの

数字の根拠と比べ方は、[AI の使用量と無料枠の目安](/ja/ai-usage-limits)にあります。一覧の **詳しく比べる** からも開けます。

![API キーでつなぐクラウドのサービスの一覧。一番上に「無料枠のあるものだけ表示」があり、各サービスが無料枠・学習・登録の 3 項目で並ぶ](/screenshots/settings-ai-free-providers.png)

- **キーを取得** を押すと、そのサービスの API キーを発行するページが開きます。
- **接続する** を押すと、キーの欄だけの画面になります。キーを貼ると自動で確かめ、そのサービスで想定しているモデルを選んでおきます。想定のモデルが無いときは、ふだん使いの系統のうち、新しいものを選びます。
- Cloudflare Workers AI では、**アカウント ID** の欄も出ます。Cloudflare のダッシュボードの右側に表示される 32 桁の ID を入れると、URL が埋まります。
- 一覧の数字は、確認した日の時点のものです。確認日から半年を過ぎると、「古くなっている可能性があります」と出ます。使う前に、各社のページで最新の条件を確かめてください。

### API キーの保存場所

キーが自分のマシンの外に出るのは、登録したプロバイダーに送るときだけです。macOS のデスクトップアプリでは macOS キーチェーンに、Windows では Graphium のデータフォルダ内のローカルファイルに保存します。権限を絞り、上限額を設定したキーを使うと安全です。詳細は [SECURITY.md](https://github.com/kumagallium/Graphium/blob/main/SECURITY.md) にあります。

### モデルごとの単価

登録済みモデルの **編集** を押すと、**単価** を設定できます。入力と出力の単価を、1M トークンあたりの USD で指定します。どちらも任意です。

よく知られたモデルなら、Graphium が参考価格を表示します。**… / … を使う** を押すと、その価格をそのまま入れられます。ここで設定した単価は、使用量タブのコスト見積もりに使われます。単価を設定していないモデルは、トークン数だけが表示されます。

## モデルの割り当て <Badge type="tip" text="v0.125.0 (2026-11-08) で変更" /> {#モデルの割り当て}

**モデルの割り当て** は、**登録済みモデル** のすぐ下にあり、最初から開いています。見出しを押すと閉じて、3 つの区分（以下、段）でいま選んでいるモデルが 1 行で出ます。ここでは、登録したどのモデルに、どの仕事を任せるかを決めます。区分は機能ごとではなく、仕事の難しさで分けています。

最初のうち大事なのは、軽い処理のモデルだけです。ほかを空欄にしておけば、AI の機能はすべて軽い処理のモデルを使います。残りは、必要に応じた調整です。

モデルを 1 つ登録すると、**登録済みモデル** は名前を並べた 1 行に閉じて、割り当てが上のほうに来ます。モデルを編集・削除するときは、見出しを押して一覧を開いてください。

割り当てには、モデルを表示名で覚えさせています。そのため、次のように動きます。

- モデルの表示名を変えると、その名前を選んでいた割り当ても、新しい名前に変わります。ほかのモデルと同じ名前に変えたときは変わりません。割り当ての欄に「（見つかりません）」と出るので、選び直してください。
- モデルを削除するときは、そのモデルを使っている割り当てが、確認の行に出ます。削除すると、それらの割り当ては空欄（既定）に戻ります。
- 改名や削除のあとで、見つからない名前が残っていると、割り当ての欄に「（見つかりません）」と出ます。選び直すか、そのまま保存すると、空欄（既定）に戻ります。
- 設定を開き直す前に名前が古くなっていても、AI の実行が別のモデルへ黙って切り替わることはありません。モデルを選び直すよう案内が出て、実行は断られます。

| 割り当て | 使われる場面 |
|---|---|
| **軽い処理のモデル** | 軽い処理に使う。[AI チャット](/ja/ai-chat-and-ask)、点検（AI 解析）、出典照合、トピックの統合、題付け、世界照合。ほかの段を空欄にしたときの行き先でもある（AI チャットは **チャットのモデル** で別に選べる）。速いモデルや、ローカルのモデル（LM Studio など）でも足りる |
| **標準の処理のモデル** | ナレッジ化、翻訳、トピックの振り分けと改訂、種類付与。空欄なら軽い処理のモデルを使う |
| **高度な処理のモデル** | URL・PDF・Word からの手順ノート作りと名寄せ、回答からの実験計画とその根拠の確認、洞察の発見、音声ノートの清書と要約（別に決めていなければ）、[じっくり調べてから答える](/ja/ai-chat-and-ask#letting-the-ai-search-again)をオンにしたときのチャットの回答（チャットのモデルを選んでいなければ）。空欄なら標準の処理のモデル、さらに空欄なら軽い処理のモデルを使う。強いモデルが向いている |
| **埋め込みモデル** | ノートとナレッジに対する意味検索。OpenAI または OpenAI 互換のプロバイダーが必要。未設定ならテキスト一致で代わりに検索する。保存前に **埋め込みテスト** を使うと、そのモデルが本当に埋め込みに対応しているかを確認できる。この欄に「（埋め込みには使えません）」が付いた名前が出るのは、設定ファイルを手で編集した場合などで、そのモデルは登録されているが OpenAI 互換のプロバイダーではないという意味。選び直すか、そのまま保存すると空欄に戻る |

**チャットのモデル** <Badge type="tip" text="v0.129.8 (2026-11-10) で追加" /> は、3 つの段とは別に、設定 → AI の **チャット** の項目にあります。

- 空欄なら、ふつうの回答は軽い処理のモデルで答えます。**じっくり調べてから答える** をオンにしたときは、高度な処理のモデルで答えます。
- モデルを選ぶと、チャットの回答がそのモデルになります。**じっくり調べてから答える** がオンのときも同じです。
- チャットとノートの題付けは、選んでもいつも軽い処理のモデルです。

チャットを難しさ別の段に入れていないのは、モデルの選び方の向きが違うためです。大量に回す仕事は安いモデルで、人が読んで一緒に考える会話は賢いモデルで、というように選びます。

### 段を使う・使わない <Badge type="tip" text="v0.125.6 (2026-11-09) で追加" /> {#段を使う使わない}

**標準の処理のモデル** と **高度な処理のモデル** の見出しの左には、スイッチがあります（**標準の処理を使う**・**高度な処理を使う**）。手元のモデルでこなせる仕事だけを使いたいときは、その段をオフにします。新しく使う人も以前から使っている人も、最初はどちらもオンです。

| オフにした段 | 画面に出なくなるもの |
|---|---|
| **標準の処理** | ナレッジに追加（ノート・メモ・素材・チャット・取り込みの一括）、翻訳、再生成、トピックの統合と作り直し、自動で整える、トピックの種類付け。知見と、知見をもとに作る洞察も使えなくなる |
| **高度な処理** | URL・PDF・Word からの手順ノート作り、回答からの実験計画、洞察（取り込み時の発見を含む）、音声ノートの清書と要約、**じっくり調べてから答える** |

- オフにしても、作ったページ・ノート・清書は消えず、そのまま読めます。オンに戻せば、入口がまた出ます。
- 選んであったモデルも、そのまま覚えています。
- **軽い処理のモデル** にはスイッチがありません。AI を使うなら、いつもこの段が動きます。
- **チャットのモデル** の欄は、高度な処理をオフにしても出ます。このとき出なくなるのは、**じっくり調べてから答える** のスイッチだけです。
- [Graphium MCP](/ja/mcp-server) から知見や洞察を作る道具は、つないだアシスタントが自分のモデルで作ります。そのため、段のスイッチには左右されません。

各段の選択欄の下には **モデルの目安** が出ます。その仕事にどの種類のモデルが向くかが、向く／条件つき／向かないで分かります。根拠は[測った結果](/ja/evaluations/model-tiers-by-feature)にあります。

![軽い処理・標準・高度の 3 段と、その下のモデルの目安](/screenshots/settings-model-guide.png)

**モデルの割り当て** の下には、それぞれ独自のオン/オフスイッチを持つセクションが、もう 2 つあります。**世界照合を使う** と **洞察を使う** です。どちらも、初めて使う人はオフ、以前から使っている人はオンになっています。オフにしても、ボタンと結果が隠れるだけです。保存済みのものは消えません。

- **世界照合**: **自動で世界照合する** のトグルがあります（既定は OFF）。オンにすると、新しく作られた洞察と知見を、裏で世界照合します。照合の仕組みとローカルの知識ベースについては、[世界照合](/ja/ai-grounding)を参照してください。世界照合には専用の選択欄がなく、いつも **軽い処理のモデル** で動きます。
- **洞察の発見**: 洞察は **高度な処理のモデル** で動きます。このセクションには、後述する **洞察のテスト** があります。

### どの仕事に、どれくらいのモデルが要るか

Graphium はどのモデルでも動きますが、仕事ごとに求められる水準は同じではありません。目安は次のとおりです。

| 仕事 | 求められること | 向いているモデル |
|---|---|---|
| 知見の抽出・トピックへの束ね・チャット | 丁寧な読み取りと忠実な抽出 | 中型以上の多くのモデルで実用になる（良質なローカルモデルを含む） |
| **洞察の生成**（知見をまたぐ抽象化） | パイプラインで最も難しいステップ。分野の発見を、空疎にせず持ち運べる規則へ引き上げる | **最上位級のモデル**。例えば Claude Opus / Claude Sonnet、あるいは各社のフラッグシップ。**モデルの割り当て** の **高度な処理のモデル** に割り当てる。「推論対応」や大きさだけでは足りないことがある。実測では、120B 級のオープンな推論モデルが知見の言い換えにとどまる一方、最上位級モデルは知見をまたぐ本物のパターンを見つけた |
| 手順の構造化（PROV 抽出） | 長い文書に対する厳密な構造化出力 | ここも最上位級モデルがいちばん安定する |
| 埋め込み（Embedding） | チャットではなく embeddings エンドポイント | embedding 対応モデル。保存前に **接続テスト** で確認する |

洞察が少ないときや、知見の言い換えに見えるときは、**高度な処理のモデル** だけを強いモデルに切り替えて、発見をもう一度実行してみてください。このように変える点を 1 つだけにして比べる手順（「変数 1 つの実験」）は、[よくある質問](/ja/faq)にまとめてあります。

### 洞察テスト <Badge type="tip" text="v0.45.0 (2026-08-25) で追加" />

おすすめを信じる代わりに、選んだモデルを実際に測れます。**洞察を使う** をオンにすると、**洞察の発見** セクションが表示されます。その中の **洞察のテスト** のブロックにあるボタンを押してください。同梱のパン作りの知見 3 件を、高度な処理のモデルで洞察にして、結果をその場に表示します。

![洞察テストと、展開したテスト用知見・期待される答え](/screenshots/settings-insight-test.png)

実行前に **テストの中身** を開くと、知見 3 件と、期待される答えが読めます。

- 知見 1・2（こね不足で潰れる／発酵しすぎで潰れる）は、「適正な範囲がある」という 1 つの規則にまとまるのが期待される答えです。
- 3 件目（今日の粉の吸水）は、まとまらないノイズです。

力のあるモデルは、この 2 件を 1 つにまとめて返します。力不足のモデルは、知見の言い換えを並べるか、何も返しません。

各候補には、引用した知見の番号が出ます。元の知見とほとんど変わらない言い回しには、**言い換えの可能性** バッジが付きます。まとまった件数と言い換えの件数を 1 行で示すサマリも出るので、候補が増えても読み解けます。

テストは、本番と同じ複数の段階を通るため、数十秒〜数分かかります。この待ち時間が、そのモデルで洞察を見つける速さの目安になります。

テストの内容は、どこにも書き込まれません。テスト用の知見はアプリの中にあります。結果も一時的なもので、アプリを閉じるまで（または **結果を消す** を押すまで）しか残りません。

## MCP サーバー <Badge type="tip" text="v0.13.6 (2026-06-04) で追加" />

MCP（Model Context Protocol）は、AI チャットが外部のツールを呼べるようにするための公開標準です。外部のツールには、Web 検索、ファイルアクセス、自分の API などがあります。Graphium は、MCP サーバーに直接つなぎます。

**外部ツールとの接続（MCP）** は、最初から開いています。その中の **MCP サーバー** の下で、**MCP サーバーを追加** を押してください。JSON を書く必要はありません。

### 選んでキーを貼る <Badge type="tip" text="v0.113.0 (2026-11-04) で追加" />

**MCP サーバーを追加** を押すと **何をつなぎますか？** が開きます。

![What do you want to connect?（何をつなぎますか？）の画面。上に Tavily（tavily.com）と Set up（設定する）ボタン、無料枠の説明。その下の Search the official list（公式の一覧から探す）では「search」の結果として、exa.ai が公開する Exa と github.com/pipeworx-io が公開する Tavily の中継版に Set up、github.com/tavily-ai の公式 Tavily には Needs Node.js or similar on this computer（Node.js などが必要）と出ている。下端に Advanced setup（詳しい設定）。](/screenshots/settings-mcp-connect.png)

- **上の一覧** は、Graphium が確かめた接続先です。今は、AI のための Web 検索 **Tavily** があります。毎月 1,000 クレジットまで無料で、ふつうの検索 1 回で 1 クレジット使います。カード登録は不要です。
  - **設定する** を押します。
  - **Tavily でキーを作る** からキーを作り、**API キー** に貼ります。
  - **つないで確かめる** を押します。Graphium は先にキーを確かめます。キーが違っていたら、もう一度コピーするよう案内し、登録はしません。

![Connect Tavily（Tavily につなぐ）の画面。公開元は tavily.com。API キーの欄が 1 つ、Get a key from Tavily（Tavily でキーを作る）のリンク、キーはこのパソコンの Graphium に保存し tavily.com につなぐときだけ使うという注記、Connect and check（つないで確かめる）ボタン。](/screenshots/settings-mcp-connect-key.png)
- **公式の一覧から探す** は、公式の [MCP Registry](https://registry.modelcontextprotocol.io) を探します。結果には、それぞれ **公開元** が出ます。この一覧には、第三者が作ったものも混ざっています。よその中継サーバーにキーを通すものもあるので、公開元を確かめてから選んでください。
  - インターネット越しにつなげるものには **設定する** が出ます。要る欄（API キーなど）は、一覧の情報から自動で作られます。
  - パソコンの中でプログラムとして動かすものには、**このパソコンに Node.js などが必要（詳しい設定から）** と出ます。これは **詳しい設定** から登録します。

**つないで確かめる** は、一覧の **接続テスト** と同じ確認をして、応答があったものだけを足します。ほかの設定と同じく、残すには設定画面の下の **保存** を押します。

### 詳しい設定

同じ枠の下にある **詳しい設定（JSON・手入力・レジストリ）** を押すと、これまでのフォームが開きます。モードは 3 つです。

| モード | 仕組み |
|---|---|
| **JSON を貼る** | サーバーの README にある `mcpServers` の JSON をそのまま貼り、**取り込む** を押す。ローカルとリモートを含む複数のサーバーを、一度の貼り付けで取り込める |
| **手動入力** | フォームを自分で埋める。**ローカル** サーバーには **コマンド**、**引数（1 行に 1 つ）**、**環境変数（KEY=value、1 行に 1 つ）** を指定する。**リモート** サーバーには **エンドポイント URL**、**トランスポート**（**SSE** か **Streamable HTTP**）、**API キー（任意）** を指定する |
| **レジストリから** | [Crucible Registry](https://github.com/kumagallium/Crucible) の **レジストリ URL** を入力し、**サーバーを取得** を押して、一覧から候補を追加する |

**ローカル** サーバーは、Claude Desktop と同じように、Graphium が stdio 経由で起動・管理します。プロセスを自分で起動したり止めたりする必要はありません。ブラウザはローカルプロセスを起動できないため、ローカルサーバーにはデスクトップアプリが必要です。**リモート** は、すでに動いているサーバーに URL で接続します。

一覧の各サーバーは、有効・無効の切り替え、編集、削除ができます。編集は、いつも詳しい設定のフォームで行います。

アプリ自身が挙げている実用的なヒントがひとつあります。検索系のサーバー（例: Tavily）を追加すると、どのモデルでも、**外部参照** でいまの Web を検索できるようになります。

### 書き換える前の確認 <Badge type="tip" text="v0.114.0 (2026-11-04) で追加" />

チャットの AI は、使う道具を自分で選んで呼びます。Graphium の外を書き換えるかもしれない道具（Slack への投稿・送信・削除など）を呼ぶ前には、Graphium が止めて、**道具を使ってよいですか？** と聞きます。ダイアログには、どのサーバーのどの道具を使おうとしているかと、**渡す内容** が 1 つずつ出ます。

- **実行する** を押すと、道具を使います。
- **実行しない** を押すか、ダイアログを閉じると、使いません。使わなかったことは AI に伝わり、AI は代わりに何をするつもりだったかを答えます。
- 5 分たっても答えなければ、使わなかったことになります。

![Allow this tool?（道具を使ってよいですか？）のダイアログ。AI が「slack」の「Post a message」を使おうとしている。What it will send（渡す内容）に channel の #bakery-lab と、28 °C で 90 分の発酵についての文。Don't ask again for "slack"（「slack」は今後確認しない）のチェックと、Don't run（実行しない）・Run it（実行する）のボタン。](/screenshots/chat-tool-approval.png)

聞くかどうかは、サーバーが道具に付けている印で決まります。

- 読むだけの印が付いた道具（Exa の検索など）は、聞かずに使います。
- 印の無い道具は、書き換えるかもしれないものとして扱い、聞きます。

読むだけのサーバーなら、**「…」は今後確認しない** にチェックを入れてください。一覧の各サーバーにある **書き換える道具は実行前に確認する** で、いつでも聞くように戻せます。確かめ済みの一覧の Tavily は検索しかしないので、聞かない設定で入ります。

**Asterism と連携する。** **先行公開の機能** で Asterism 連携をオンにしていると、サーバー一覧の下に **Asterism を探してつなぐ** ボタンが出ます。このボタンは、起動中の Asterism を探します。デスクトップ版はポート 8765、`asterism-local` は 8080 です。見つけたら、その `/mcp` を **asterism** として登録し、接続テストまで済ませます。

以後、チャットの AI は、Asterism の知識グラフに問い合わせられます。どんなデータセットがあるか、行に何が書いてあるか、その表がどこから来たかを聞けます。

ここでの Graphium は、外のツールを呼びに行く**クライアント**の側です。Graphium は、逆に MCP **サーバー**としても動きます。その場合は、Graphium の外にいるアシスタント（Claude Desktop、Claude Code、Cursor など）が、あなたのノートを外から読めます（[AI アシスタントから使う](/ja/mcp-server)）。両者は独立した設定です。

## 使用量タブ <Badge type="tip" text="v0.12.0 (2026-05-28) で追加" />

設定の **使用量** タブには、**AI 使用量** が表示されます。AI 機能ごとのトークン消費量が並ぶので、費用が実際にどの機能に使われているかが分かります。

- 期間は **日** / **月** / **年** で切り替えます。タブには、**合計トークン**、**想定コスト**、**時系列のトークン** のグラフ、**機能別の内訳** が表示されます。
- コストは USD か JPY で表示されます。通貨は切り替えられ、換算レート（**1 USD = ¥**）はその場で編集できます。
- サブスクリプションのモデルには **Subscription（従量課金なし）** と付きます。トークンは数えますが、コストは見積もりません。
- あとからモデルの単価を変えた場合は、**コストを再計算** を押すと、直近 90 日分の記録を現在の単価で計算し直せます。それより古い月次集計は変わりません。

![設定の Usage タブ。Month を選び、Total tokens と Estimated cost、高さの違う月ごとの Tokens over time の棒グラフ、全機能に費用が付いた By feature の内訳、USD/JPY の切り替えと 1 USD = ¥ のレート、Recalculate cost ボタンが見える。](/screenshots/settings-usage-tab.png)

使用量の記録はバックエンドで動くので、デスクトップアプリの機能です。
