# AI アシスタントから使う（MCP）<Badge type="tip" text="v0.46.0 (2026-08-28) で追加" />

Graphium は **MCP サーバー**としても動きます。Graphium の外にいる AI アシスタント — Claude Desktop、Claude Code、その他の [MCP](https://modelcontextprotocol.io) クライアント — が、あなたのノートの中を見たり、新しいノートを書き足したり、ナレッジ層の手入れを手伝ったりできるようになります。

::: tip 「AI のセットアップ」の MCP サーバーとは逆向きの話です
[あちら](/ja/ai-setup#mcp-サーバー)は Graphium が**クライアント**になって、自分の AI チャットから外のツールを呼びに行く設定です。このページは Graphium が**サーバー**になって、外のアシスタントがあなたのノートを見に来る設定です。両者は独立しているので、どちらか一方でも、両方でも、どちらも使わなくても構いません。
:::

Graphium を開いて、目当てのノートを探して、手順をチャット欄に貼り付ける、という手間の代わりに、アシスタントに直接尋ねられます。

> 「CuGaTe2 をボールミリングしたときの条件は？」

アシスタントはあなた自身のノートから答えを読み、どのノートから来たのかも一緒に示します。

## どんなときに役立つか

- **自分のノートに質問する。** アシスタントが一般知識から推測するのではなく、あなたの記録を検索して答えます。
- **自分の実験どうしを比べる。** 「グラファイトダイを使った試行はどれか」は、一般的なモデルには答えられず、あなたのノートには答えられる問いです。
- **手順を会話に持ち込む。** 手順は順番どおりに返り、それぞれの材料・道具・条件が付いてきます。
- **結論を書き戻す。** 会話の中で残す価値のあるものができたら、アシスタントが新しいノートとして書き込めます。
- **資料そのものを読む。** PDF（ページ単位）・Word・Graphium に登録済みの Web ページの本文を、トピックの要約に頼らず直接読めます。
- **手順の流れを図で見る。** ノートの手順を Mermaid のフローチャートで受け取れます。文書にそのまま貼れます。
- **ナレッジのページを手入れする。** 重複したトピックをまとめる、トピックや問答ページを書き直す、アーカイブする、といったことを任せられます。すべて記録され、Graphium からも取り消せます。

ノートは、アシスタントが読み取った答えという形以外では手元から出ません。読む・探す・ノートを足すことは、Graphium を閉じていても開いていても動きます（サーバーがノートのファイルを直接読むためです）。例外は **ナレッジのページの手入れで、こちらは Graphium を終了してから** 行います。アプリは起動中、自分の索引を正としているので、外からの書き換えが次の起動まで反映されず、上書きされることがあるためです。起動中は `APP_RUNNING:` と答えて断ります。

## 設定する

全体の流れは「サーバーを 1 回ビルドする → 使うアプリに登録する → 動くか確かめる」の 3 段です。一度登録すれば、あとは普段どおり話しかけるだけです。

必要なもの:

- [Node.js](https://nodejs.org/) 20.16 以降（PDF の読み取りに使う pdfjs の要件です）
- Graphium のソースコード（デスクトップ版のアプリには MCP サーバーが入っていないため、ソースからビルドします）
- [pnpm](https://pnpm.io/)（無ければ `npm install -g pnpm`）

**1. サーバーをビルドする。** ソースを取得して、そのフォルダで実行します。

```bash
git clone https://github.com/kumagallium/Graphium.git
cd Graphium
pnpm install
pnpm bundle:mcp
```

`dist-mcp/graphium-mcp.mjs` という 1 つのファイルができます。このファイルのフルパスを次の手順で使います（`pwd` で表示されるフォルダの後ろに `/dist-mcp/graphium-mcp.mjs` を付けたもの）。

PDF と Word の文字起こしは、clone 側の `node_modules` を使います。**`graphium-mcp.mjs` を別の場所へ写して使うと、この 2 つ（PDF と Word の文字起こし）だけが使えなくなります**（ほかのツールは動きます）。`pnpm bundle:mcp` が作った場所のまま使ってください。

あわせて `node` 自体のフルパスも控えておきます。デスクトップアプリはターミナルと違って `PATH` を引き継がないことがあり、`"command": "node"` だけでは起動できない場合があるためです（nvm で Node を入れている場合は特に）。

```bash
which node
```

**2. 使うアプリに登録する。**

*Claude Code の場合* — ターミナルで次を実行します。`--scope user` を付けると、どのフォルダで Claude Code を開いても Graphium のノートを引けるようになります（付けないと、実行したフォルダでしか使えません）。

```bash
claude mcp add --scope user graphium -- /path/to/node /path/to/Graphium/dist-mcp/graphium-mcp.mjs
```

*Claude Desktop の場合* — **設定 → 開発者 → 構成を編集** で開く設定ファイル（macOS では `~/Library/Application Support/Claude/claude_desktop_config.json`）の `mcpServers` に `graphium` の項目を足します。

```json
{
  "mcpServers": {
    "graphium": {
      "command": "/path/to/node",
      "args": ["/path/to/Graphium/dist-mcp/graphium-mcp.mjs"]
    }
  }
}
```

::: warning 先に Claude Desktop を終了してから書き換えます
この設定ファイルには、アプリ自身の設定も一緒に保存されています。アプリを起動したまま書き換えると、終了や再起動のときにアプリが手元の古い内容で書き戻し、足した `graphium` が消えることがあります。**⌘Q（Windows はタスクトレイから終了）でアプリを完全に終了してから**ファイルを書き換え、保存してから起動してください。ほかの項目（`mcpServers` の別のサーバーや `preferences`）は残したまま、`graphium` だけを足します。
:::

パスはどちらも、相対パスではなくフルパスで書きます。

**3. 動くか確かめる。** Claude Desktop は新しい会話を始めるだけでは足りず、アプリごと起動し直す必要があります。Claude Code は新しいセッションを始めます。そのうえで、次のように尋ねます。

> 私のノートにはどんなトピックがある？

トピックの一覧が返ってくれば完了です。Claude Code では `claude mcp list` を実行すると、`graphium` が `✓ Connected` になっているかも確かめられます。

### ほかの MCP クライアント

ここに Claude 固有のものはありません。Graphium は標準のプロトコルを stdio で話すので、**ローカルの MCP サーバーを起動できるクライアントであれば動きます** — Cursor、VS Code、Zed、Cline など。どのクライアントでも必要なのは同じ 2 つ、`node` というコマンドと、`graphium-mcp.mjs` へのフルパスです。

それをどこに書くかはクライアントによって違い、しかもこの設定はバージョンによって移動しがちです。正確な場所と書式は、お使いのクライアントの MCP ドキュメントを確認してください。上の `mcpServers` の JSON をそのまま受け取るものも多くあります。

| クライアント | 追加のしかた |
|---|---|
| Claude Desktop | 設定 → 開発者 → 構成を編集 |
| Claude Code | `claude mcp add graphium -- node <パス>` |
| Cursor / VS Code / Zed / Cline など | それぞれの MCP 設定（多くは同じ形の JSON） |

制約が 2 つあります。サーバーは**ローカルのプロセス**として動きます（接続先の URL があるわけではなく、リモート HTTP には対応していません）。また、クライアントを動かすマシンに **Node.js 20.16 以降**が必要です。ノートは手元のディスクにあるので、クライアントも vault と同じマシンにいる必要があります。

サーバーは既定で `~/Documents/Graphium` を読みます。**⚙ 設定 → 一般** で Graphium のフォルダを変更している場合は、その設定に自動で従います。別の場所を明示したいときは `env` を足します。

```json
{
  "mcpServers": {
    "graphium": {
      "command": "node",
      "args": ["/absolute/path/to/Graphium/dist-mcp/graphium-mcp.mjs"],
      "env": { "GRAPHIUM_ROOT": "/Users/you/Dropbox/Graphium" }
    }
  }
}
```

### 新しい版に更新する

MCP サーバーは、ビルドした時点の Graphium のまま動き続けます。デスクトップ版の自動アップデートでも新しくなりません。ソースを更新したら、ビルドし直してからアプリを起動し直してください。

```bash
cd Graphium
git pull
pnpm install
pnpm bundle:mcp
```

登録はそのままで構いません（同じパスのファイルが新しくなるだけです）。新しいツールが表に載っているのにアシスタントが使えないときは、たいていビルドし直しを忘れています。

### `create_note` の数式と上付き・下付き

本文は Markdown です。見出し・箇条書き・コードブロック・表・太字・斜体・インラインコード・リンクに加えて、数式と上付き・下付きも読み取ります。書き方は `get_note` がノートをアシスタントに渡すときと同じです。文中の数式は `$…$`、独立した数式は行に単独の `$$ … $$`、10⁵ や H₂O の上付き・下付きは `<sup>` / `<sub>` で表します。そのため、アシスタントがあなたのノートを引用して新しいノートを作っても、`$x$` や `<sup>5</sup>` は文字のまま残らず、数式と上付きとして保存されます。`$100 と $200` や `$50-$75` のような金額は、数式にならず文字のままです。

### `create_note` の citations

`create_note` には `title` と `body` のほかに、任意の引数が 2 つあります。

- **`citations`** — 回答が引いた Graphium 内のノート/ページを表す `{ id, title? }` の配列。指定すると本文末尾に References 節が付きます。`id` が実在するノートを指していれば、トピックが出典から作る References 節と同じ見た目の `@` リンクになります。`id` が解決できない場合はリンクにせず、文字のまま残ります（黙って消えることはありません）。

どちらも追加のみの変更で、指定しなければ従来どおりの挙動です。

### `create_note` と `save_answer` の使い分け

どちらも vault に新しいものを書き足しますが、置き場所が違う層で、Graphium がその後の扱い方も層ごとに変えます。

- **`create_note`** は**ノート**を作ります — 人が保守するものです。Graphium はその後、自分からは一切手を触れません。
- **`save_answer`** は**問答（Q&A）ページ**を作ります — ナレッジ層のページです（アプリ内チャットの「ナレッジに残す」ボタンが作るのと同じ `answer` 種別）。作られたあとは、関連する資料が取り込まれるたびに Graphium が改訂し、ほかのナレッジ層のページと同じく点検・出典照合の対象になります。アプリ内のボタンとの違いが1つあります。「ナレッジに残す」は保存前に会話を渡して単体で読める記事に書き起こしますが、`save_answer` は外部クライアント側の会話に Graphium から手が届かないため、渡された `question`/`answer` をそのまま保存します。本文はあらかじめ単体で読める形にして渡してください。

ノートが増えるにつれて Graphium に面倒を見続けてほしいものは `save_answer`、自分で保守するつもりの一回きりの記録は `create_note` を使います。

`save_answer` に渡す本文では、**根拠のある文の文末に `[[source:<id>]]` を書いてください**（id は `citations` に渡すもの。同じことを複数の資料が述べているなら並べて書けます）。出典照合は文ごとに「その文が引いた資料に本当に書いてあるか」を照らすので、本文に引用が 1 つも無い問答（Q&A）ページは照合の対象になりません。引用が無いまま保存すると、ツールの返事でその旨を知らせます。

`save_answer` の引数:

- **`question`** — ページのタイトルになります。
- **`answer`** — 本文（Markdown）。vault 内のものを引用する箇所には `[[source:<id>]]` と書きます。
- **`citations`** — `{ id, title? }` の配列。`create_note` と同じ形です。`answer` 中の各 `[[source:<id>]]` はこの一覧と照らして解決され、末尾に References 節が付きます。実在するノート/ページを指す `id` は `@` リンクになり、解決できない `id` は文字のまま残ります。
- **`sessionId`**、**`model`** — `create_note` と同じく、来歴として記録されます。

`save_answer` の呼び出しが終わると、`create_note` で作ったノートと同じく、再読み込み後に Graphium 側に表示されます。

### 資料を読む <Badge type="tip" text="v0.87.0 (2026-10-07) で追加" /> {#資料を読む}

`get_source_text` は、資料の本文を**窓**に切って返します。長い資料でも少しずつ読めます（既定は 4,000 字ずつ、窓どうしは 400 字重なります）。続きを読むときは、アシスタントが次の窓を頼みます。

- **PDF** — 窓ごとに、どのページにあたるか（「ページ n〜m」）を示します。ページを直接指定すると（「3 ページ目あたりを読んで」）、そのページを含む窓が返ります。
- **Word** — `.docx` だけに対応しています。ほかの形式（`.xlsx`・`.pptx`・古い `.doc`）は `UNSUPPORTED_FORMAT` と答えます。
- **Web ページ** — Graphium に登録済みの URL だけです。その場で**ネットワークから取り直して**読むため、取り込んだときに保存した内容ではなく、いまのページの内容です。
- **ノート** — ノート ID を渡すと、そのノートの本文が返ります。

資料の id（`pdf:…` / `document:…` / `url:…`）は `get_topic` や `search_media` の結果に出てきます。そのため「このトピックが引いている資料を読んで」と頼むだけで、こちらが調べなくても済みます。

### アシスタントからナレッジのページを手入れする <Badge type="tip" text="v0.87.0 (2026-10-07) で追加" /> {#アシスタントからナレッジのページを手入れする}

**手入れ** 画面で行うようなナレッジ層の手入れを、アシスタントに任せられます。対象は**トピックと問答ページだけ**です。ノート・知見・洞察には触れません。

| ツール | できること |
|---|---|
| `revise_topic` | 本文を Markdown で書き直します。根拠のある文の文末に `[[source:<id>]]` を付けます。渡す資料 id は Graphium に実在する必要があり、無いものは `UNKNOWN_SOURCE` で断ります。資料を渡さないときは、今の資料のままです |
| `merge_topics` | トピックを 1 つにまとめます。残す側の本文を渡すと、吸収される側はゴミ箱へ移ります |
| `archive_page` / `restore_page` | ページをアーカイブする／アーカイブやゴミ箱から戻す |
| `list_operations` | 最近の手入れの操作を一覧します（アプリで行ったものも含み、取り消せるかどうかも出ます） |
| `undo_operation` | 操作を 1 回で取り消します。先に、何が変わるかの見積もりを返します。操作のあとにそのページが編集されている場合や、出典照合の結果も一緒に戻る場合は、`confirm: true` を付けて呼び直す必要があります |

安全のための決まりは次のとおりです。

- **どの変更も記録され、取り消せます。** 操作は Graphium の **手入れ → 操作の記録** に「MCP（クライアント名）」として、アプリで行った操作と同じ並びで出てきて、そこからも取り消せます（[手入れの操作は取り消せます](/ja/knowledge-layer#undo-maintenance)）。MCP から行った取り消しも、それ自体が操作として残り、取り消せます。
- **版は作られません。** MCP 経由の書き換えでは、履歴パネルに版は残りません。戻すときは操作の記録から行います（写しは 1 年保管されます）。
- **`restore_page` は記録に残りません**（アプリでアーカイブを解除するときと同じです）。
- **Graphium を終了してから使います。** アプリが起動中は `APP_RUNNING:` と答え、何も変えません。
- **2 つの MCP が同時に書くとき**は、あとから来たほうが `BUSY:` と答え、先のものが終わるまで待ちます。
- **Graphium を一度も起動していない vault** には `note-index.json` が無いため、`NO_INDEX:` と答えます。Graphium を一度起動して終了してから、もう一度お試しください。
- **古い形式のトピック**（知見から作ったもの）は `OLD_FORMAT:` と答えます。先に Graphium で **資料から作り直す** を行い、新しい形式にしてください。

変更は、次に Graphium を起動したときに反映されます。ほかに 2 つ、あとから追いつくものがあります。素材の「使っているノート」と、そのページの意味検索（埋め込み）です。次にアプリでそのページを保存・再埋め込みしたときに更新されます。

### ノートとナレッジ層

Graphium はノートの上にナレッジ層を組み立てます。**知見(claim)** はノートから抽出された、出典つきの命題。**トピック(topic)** は資料を読んで概念ごとにまとめたページ。**洞察(insight)** は複数の知見にまたがるパターンです。`search_notes` は `kind` で絞り込めます — `note` / `topic` / `claim` / `insight`、またはナレッジ層すべてをまとめて表す `wiki`。どのヒットもどの種別かを返します。

`list_topics` は Graphium がまとめたものの全体像をいちばん早くつかめる方法です。タイトルと 1 行要約がトピックごとに並びます（Karpathy が LLM 向け wiki で説明している「まず索引を読む」やり方と同じです）。`get_topic` はトピック 1 件を開き、本文と出典を一度に返します — 資料から作ったトピックは本文が引いている資料、以前の形式（知見から作ったトピック）は束ねている知見と各知見の出どころノートです。

返ってくる答えにはノート ID とブロック ID が付いています。アシスタントは出どころを正確に示せますし、あなたはその箇所を Graphium で開けます。

### 返ってくるものの例

手順を尋ねると、順番と、各手順が何を使ったかが返ります。

```
# 多結晶CuGaTe2のボールミリング条件と熱電特性 の手順（9 件）

1. 溶融  [blockId: 801e35ed-…]
   material: Cu, Ga, Te
   tool: シリカ管
   attribute: 99.99%, 99.999%
   純度99.99%のCu、純度99.99%のGa、純度99.999%のTeをシリカ管に封入し、直接反応によって溶融する。

3. ボールミリング  [blockId: b2cd7d10-…]
   material: 粉末
   tool: プラネタリーボールミル, WC ボール
   attribute: rpm: 300, ball-to-powder ratio: 2:6:1, atmosphere: Ar, time: 0 h
```

同じ装置を使ったノートを尋ねると、その一覧が、ノートごとの該当ブロックつきで返ります。

```
■ tool: グラファイトダイ  — 3 ノート
   - 多結晶CuGaTe2のボールミリング条件と熱電特性  [noteId: 70ac6b8a-…, blockId: 540904a1-…]
   - CuGaTe2 のボールミリング条件が熱電特性に与える影響  [noteId: 585e605f-…, blockId: d22a6e98-…]
```

### 尋ねてみるとよいこと

ツール名を指定する必要はありません。普通の言葉で尋ねれば、アシスタントが選びます。次のような問いが向いています。

- **「グラファイトダイを使った実験はどれ？」** — 一般的なモデルには答えられない比較です。あなたの記録が要るためです
- **「CuGaTe2 のボールミリングの手順を、各ステップの条件つきで教えて」** — 手順を会話に持ち込んで、そこから条件を変えて考えられます
- **「私のノートにはどんな装置や材料が出てくる？」** — 自分が何を記録してきたかの輪郭が見えます
- **「今回は 873 K でやった。前回までと比べてどう？」** — 自分のノートを基準線にして考えられます
- **「この結論はどこから来たの？」** — 来歴をさかのぼって、派生元のノートや、取り込んだ元の PDF・Word・Web ページまで辿ります
- **「その資料から作られたノートやトピックは他にある？」** — 資料の側から、そこから生まれたものを辿ります
- **「いま整理できたことを、こういうタイトルでノートにして」** — 会話の結論を手元に書き戻せます
- **「この手順を図にして」** — 手順を Mermaid のフローチャートで返します（60 手順まで）
- **「重複しているトピックをまとめて」** — 重複を見つけてまとめ、取り消せるように記録します（Graphium を終了してから）
- **「この PDF の 3 ページ目あたりを読んで」** — トピックの要約ではなく、資料そのものを読みます

出どころのノートを一緒に尋ねる癖をつけておくとよいかもしれません。アシスタントは ID を持っているので「それはどのノート？」には必ず答えられますし、Graphium で開いて確かめられます。

### 一連の流れの例

論文の下書きや解析コードを Claude Code で書きながら、手元の記録を参照する場合の流れです。

1. **全体を見る** — 「私のノートにはどんなトピックがある？」（`list_topics`）
2. **深掘りする** — 「Zn4Sb3 の合成条件について分かっていることを教えて」（`get_topic`）。本文と、根拠にした資料の名前が返ります
3. **確かめる** — 「単相にならなかった回の手順を条件つきで見せて」（`search_notes` → `get_note_steps`）。気になったら、返ってきたノート ID のノートを Graphium で開きます
4. **書き戻す** — 「いまの整理を『Zn4Sb3 は焼結し直すと ZnSb に分解しやすい』というノートにして」（`create_note`）。Graphium を再読み込みすると一覧に出ます

手入れの流れは少し違います。先に Graphium を終了してから、次のように進めます。

1. **気になる所を探す** — 「ナレッジに重複がないか点検して」（`check_knowledge`）
2. **まとめる** — 「その 2 つの Zn4Sb3 のトピックをまとめて」（`merge_topics`）。アシスタントがまとめた本文を書き、吸収される側はゴミ箱へ移ります
3. **確かめる** — 「いま何を変えた？」（`list_operations`）
4. **違っていれば取り消す** — 「それを取り消して」（`undo_operation`）。結果を見るには、そのあとで Graphium を起動します

### ラベルがあると効き方が変わります

`find_notes_using` と `list_entities` は、ノート本文に付けた **材料 / 道具 / 条件 / 出力** のハイライトを読みます。まだ何もラベルを付けていない場合、この 2 つは材料を持ちません（検索やトピックなど、ほかのツールはそのまま使えます）。

ここがラベルを付けることの見返りです。いくつかのノートが同じ装置の名前を持つようになると、「この装置を使った実験はどれだったか」を、そのまま尋ねられるようになります。[ラベルと来歴](/ja/labels-and-provenance)も参照してください。

## あえてやらないこと

**既存のノートを書き換えることはありません。** `create_note` は新しいノートを足すだけです。`save_answer` も新しい問答（Q&A）ページを足すだけで、あなたのノートには触れません（ただし作られた問答（Q&A）ページ自体は、ノートと違って Graphium のナレッジ層の保守によって後から改訂されます）。MCP 経由でアシスタントが行うどの操作も、あなたが書いた**ノート**を上書きしません。

**ナレッジのページは手入れできます。どの変更も記録され、取り消せます。** トピックと問答ページは、書き直し・統合・アーカイブができます（[前の節](#アシスタントからナレッジのページを手入れする)）。どれもクライアント名つきで操作の記録に残り、Graphium から取り消せます。Graphium が起動しているあいだは断られ、履歴パネルの版は作られません。戻すのは操作の記録からです。

**点検は機械判定だけです。** `check_knowledge` は、孤立したページ・空のページ・同名の重複・資料の欠落・矛盾の印を見つけます。AI を使う判定（古さ・穴・意味が同じ重複）は、Graphium の手入れ画面で行います。手順の図は 60 手順までで、それを超えると先頭の 60 手順と注記になります。

**来歴を作り出すことはしません。** 実験について会話すれば来歴グラフができあがる、と期待されるかもしれませんが、そうはしていません。これは意図的なものです。来歴は、実際に起きたことの記録です。会話から組み立て直したグラフは、見た目は同じでも意味が違います。それはあなたの手順についての推測であり、照らし合わせる相手がありません。Graphium は、エディタであなたが行ったことから来歴を記録します。モデルが「たぶんこうしたのだろう」と推測したものからは記録しません。

一方で、**書き込みが起きたという事実そのもの**は自動で記録されます。MCP 経由で作られたノートには、誰の依頼で、どのクライアントを通って、どのモデルが書いたのかが残ります。これは推測ではなく観測なので、記録として残せます。

**MCP で作ったノート・問答（Q&A）ページは再読み込み後に現れます。** どちらの一覧もアプリ側が組み立てるため、Graphium を開いたまま書き込んだものは、次に再読み込みするか再起動したときに一覧に出ます。手入れのツールによる変更は、次に Graphium を起動したときに反映されます。

## うまくいかないとき

**クライアントに Graphium のツールが出てこない。** 設定のパスがフルパスになっていて、実在する `graphium-mcp.mjs` を指しているかを確認し、クライアントをアプリごと再起動してください。Claude Desktop では **設定 → 開発者** でサーバーが起動したかどうかを確認できます。

**Claude Desktop を再起動したら、足した設定が消えていた。** アプリを起動したまま設定ファイルを書き換えると、アプリが古い内容で上書きします。⌘Q でアプリを完全に終了してから、もう一度書き換えてください（[設定する](#設定する)の注意を参照）。

**サーバーが起動しない（ログに `spawn node ENOENT` など）。** デスクトップアプリが `node` を見つけられていません。`which node` で調べたフルパスを `"command"` に書いてください。

**Claude Code で、あるフォルダでは使えるのに別のフォルダでは使えない。** 登録したときに `--scope user` を付けなかったため、そのフォルダ専用になっています。`claude mcp add --scope user …` で登録し直してください。

**マニュアルに載っているツールが出てこない・動きが古い。** サーバーのファイルがビルドしたときのままです。[新しい版に更新する](#新しい版に更新する)の手順でビルドし直してください。

**手入れのツールが `APP_RUNNING:` と答える。** Graphium が起動しています。完全に終了してから、もう一度お試しください。ブラウザ版は、閉じたあとも 90 秒ほど起動中に見えることがあります。

**手入れのツールが `BUSY:` と答える。** 別の MCP が書き込んでいる最中です。少し待ってからもう一度お試しください。

**手入れのツールが `NO_INDEX:` と答える。** vault に `note-index.json` がありません。Graphium を一度も起動していない vault です。Graphium を一度起動して終了してから、もう一度お試しください。

**PDF を読むと「Node 20.16 以上が必要」と出る。** Node.js を 20.16 以降に更新してください（`"command"` にはその `node` のフルパスを書きます）。

**PDF と Word の文字起こしだけが動かず、ほかは動く。** bundle を clone の外へ写して使っています。clone の `dist-mcp/` にあるファイルをそのまま使うか、クライアントの設定をそのパスに戻してください。

**ツールが「vault が見つかりません」と答える。** ノートのフォルダを見つけられていません。`env` の `GRAPHIUM_ROOT` に、`notes/` を含むフォルダを指定してください。

**ノートがあるのに検索で何も出てこない。** サーバーは最初の検索時に自前の索引を組みます。ノートが多いと 1 秒ほどかかります。それでも空のままなら、指定したフォルダが Graphium の実際の保存先かどうかを確認してください。現在のパスは **⚙ 設定 → 一般** に表示されています。
